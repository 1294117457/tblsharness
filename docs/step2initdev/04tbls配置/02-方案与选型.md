# 02 方案与选型

## 一、用户提的 4 个方案

| 编号 | 方案 | 一句话 |
| :-- | :-- | :-- |
| 1 | **默认路径先放一个 tbls.exe** | 随插件 ship 一个默认的 `tbls.exe` |
| 2 | **手动指定电脑上的 tbls.exe** | 设置里增加选择文件按钮 |
| 3 | **找不到时提示手动指定** | 默认失败 → 引导用户去设置 |
| 4 | **自动下载** | 旁边加一个按钮，自动从 GitHub Releases 拉取 |

这些方案不互斥——1/2/3 是"tbls 怎么来"，4 是"怎么帮用户搞到 tbls"。

下面把用户提的 4 项拆成 5 个清晰可比较的方案（多一个"提示 + 一键复制命令"）。

## 二、5 个候选方案

| 方案 | 做法 | 优点 | 缺点 |
| :-- | :-- | :-- | :-- |
| A. **随插件 ship 跨平台二进制** | 扩展包里放三个平台各一份 `tbls.exe`/linux/darwin，激活时按 `process.platform` / `process.arch` 拷到 `globalStorage/bin/tbls` 并加可执行位（Windows 跳过），设置默认指向它 | 零依赖；离线能用 | **VS Code Marketplace 审核不过**（不允许塞非常规可执行文件）；60 MB 包体积；tbls 升级要重新发版；不同平台扩展 ID 不互通 |
| B. **首次激活时下载到 globalStorage** | 激活时若无 `globalStorage/bin/tbls`，按当前平台从 GitHub Releases 拉一份；以后启动直接用 | 包体积小；tbls 升级只需扩展升级；和方案 A 实际等价但符合政策 | 首次启动**必须有网**；需要版本管理（`tbls.version` 字段）；下载失败要回退到方案 D |
| C. **用户从设置里手动选文件** | `harness.tblsPath` 旁边加"浏览…"按钮，挑一个文件（`*.exe` / 无后缀） | 用户掌控力强；不改 ship 内容；和现有路径兼容 | 新用户依然卡在"装 tbls" |
| D. **默认走 `PATH` 的 `tbls`，找不到时引导** | 保持现状（默认 `"tbls"`），但报错对话框改成"选择文件 / 在终端运行 [brew/scoop install tbls] / 打开 GitHub Releases 页面 / 复制安装命令" 4 个选项 | 实现成本最低 | 仍然要用户装；和现状差距小 |
| E. **B + C + D 组合（推荐）** | ① 首次激活按平台 / 架构从 GitHub Releases 下载到 `globalStorage/bin/tbls`（带版本号和 sha256 校验），设置 `harness.tblsPath` 默认指向它；② 设置里加"浏览…"按钮覆盖默认；③ 下载失败 / 校验失败时退回方案 D 的引导；④ 手动指定优先于默认 | **新用户开箱即用**；**老用户不打扰**；下载失败有兜底；符合 Marketplace 政策；tbls 升级可控 | 实现成本中等（下载 + 校验 + 平台选择 + UI） |

## 三、评估矩阵

| 维度 | A | B | C | D | E |
| :-- | :--: | :--: | :--: | :--: | :--: |
| 新用户上手成本 | 🟢 零 | 🟢 零 | 🔴 高 | 🔴 高 | 🟢 零 |
| 老用户（自带 tbls） | 🟡 默认覆盖要修 | 🟡 默认覆盖要修 | 🟢 保持 | 🟢 保持 | 🟢 默认值仍是 `globalStorage/...`；老用户改成自己路径即可 |
| VS Code Marketplace 合规 | 🔴 否 | 🟢 是 | 🟢 是 | 🟢 是 | 🟢 是 |
| 首次启动可不联网 | 🟢 可 | 🔴 不可（缺网时退回 D） | 🟢 可 | 🟢 可 | 🟡 缺网时退回 D，行为同现状 |
| tbls 升级路径 | 🔴 跟扩展版本 | 🟡 扩展新版本触发提示 / 手动 | 🟢 包管理器 | 🟢 包管理器 | 🟡 同 B，但提供"检查更新"按钮 |
| 包体积影响 | 🔴 +60 MB | 🟢 0 | 🟢 0 | 🟢 0 | 🟢 0 |
| 维护负担 | 🟡 三平台都跟 | 🟡 release 列表解析 + 校验 | 🟢 低 | 🟢 低 | 🟡 同 B |
| 隐私 / 安全 | 🟡 二进制固定版本要锁 | 🟡 sha256 校验 + 官方源 | 🟢 无 | 🟢 无 | 🟡 同 B + 用户可控 |
| Cursor 兼容 | 🟡 同 VS Code | 🟢 同 | 🟢 同 | 🟢 同 | 🟢 同 |
| 实现成本（人天） | 1–2 | 2–3 | 0.5 | 0.5 | 3–4 |

> 颜色：🟢 优 / 🟡 中 / 🔴 差

## 四、推荐

**方案 E：B + C + D 组合**。理由：

1. **新用户真正零成本**。下载到 `globalStorage` 后用户完全无感；下载失败才回退到引导。
2. **不违反 Marketplace 政策**。tbls 二进制按需下载，不打包进扩展。
3. **保留老用户的自由**。自带 tbls 的用户可以一键指向自己机器上的版本，插件不会用 globalStorage 里的版本覆盖他。
4. **tbls 升级可控**。`harness.tblsPath` 仍然是单一入口；提供一个"检查新版本"按钮，**不**做自动更新。
5. **隐私 / 安全**。只从 GitHub Releases 拉，二进制带 sha256 校验；用户随时可以改成自己的路径或文件，插件不锁版本。

方案 A 看似更省事（"零依赖、离线能用"），但和 Marketplace 政策冲突 + 三平台体积 + tbls 升级要发版的代价，把"省事"全部花在了不该花的地方。

方案 C 和 D 单独都不解决"新用户要装 tbls"的核心痛点，留作方案 E 的兜底组件。
