## 一、先确认"以 tbls JSON 为标准"这条路走得通

我看了 tbls 读取 JSON 的源码（`tbls/datasource/datasource.go` 第 248 到 266 行），有两个对你有用的结论：

1. tbls 读 JSON 时会忽略它不认识的字段。 它用的是 Go 标准的 `json.NewDecoder`，没有开启"拒绝未知字段"的选项。所以设计 JSON 里多写一些字段，tbls 依然能读。

不过 tbls 的 JSON Schema 规定了 `additionalProperties: false`，严格校验时这些多出来的字段会报错，以后 tbls 升级也可能改变这个行为。所以建议设计 JSON 严格遵守 tbls 格式，扩展信息单独放一个文件：

design/schema.json   # 严格是 tbls 格式：表、字段、关系、注释，tbls 能直接渲染

design/ext.json      # 你的扩展：关系类型（logical、json_array、polymorphic）、稳定 ID、状态机、和数据库表的映射

2. Windows 下 `json://` 的路径写法。 源码是直接按 `json://` 切分字符串，取后面的部分当文件路径，所以写成下面这样就行：

tbls doc json://E:/codes/demo/.harness/design/schema.json E:/tmp/design-doc -f

## 二、Cursor 插件的开发方式

| 事项            | 做法                                                         |
| :-------------- | :----------------------------------------------------------- |
| 插件框架        | VS Code Extension API，用 TypeScript 写                      |
| 调试            | 在 Cursor 里按 F5，会打开一个"扩展开发宿主"窗口，插件在这个窗口里运行 |
| 本地安装        | 用 `vsce package` 打包出 `.vsix` 文件，在 Cursor 里选择"从 VSIX 安装" |
| 发布            | Cursor 的插件市场来自 Open VSX，用 `ovsx publish` 发布（不是微软的 VS Code 市场） |
| 界面            | Webview 里运行 Vue3 + Vite 构建出来的页面                    |
| ER 画布         | Vue Flow：它是 React Flow 的 Vue 版本，MIT 许可证，你用起来最顺手；自动布局用 elkjs |
| 其他图          | Mermaid                                                      |
| 存储密码        | 用插件 API 提供的 `context.secrets`，底层是系统的凭据管理，不要写进文件 |
| MCP（第二阶段） | 用 `@modelcontextprotocol/sdk` 写一个 TS 版的 MCP Server。注册到 Cursor 有两种方式：在工作区写 `.cursor/mcp.json`，或者用 Cursor 提供的 MCP 扩展 API 在插件里注册（具体 API 请以 Cursor 官方文档为准） |

注意：微软以前提供的 `@vscode/webview-ui-toolkit` 已经停止维护，不要再用。Webview 里的样式可以直接使用 VS Code 提供的 CSS 变量（比如 `var(--vscode-editor-background)`），这样界面能自动跟随编辑器的主题。

Java 和 Spring Boot 什么时候会用到？ 以后如果要做团队共享、服务端存储、多人协作，可以用 Spring Boot 做后端。第一版不要引入，否则用户必须先装 Java，插件体积和启动速度都会变差。

## 三、插件项目结构建议

harness-cursor/

├─ package.json              # 插件声明：命令、侧边栏视图、配置项

├─ src/

│  ├─ extension.ts           # 插件入口

│  ├─ tbls/runner.ts         # 调用 tbls out -t json --sort

│  ├─ model/

│  │  ├─ tbls.d.ts           # 从 tbls 的 JSON Schema 自动生成的类型

│  │  ├─ normalize.ts        # 适配器：统一 schema 前缀、逻辑类型、主键标记、enum 关联、过滤噪音

│  │  └─ ext.ts              # design/ext.json 的类型

│  ├─ diff/                  # design 和 db 的结构对比

│  └─ webview/panel.ts       # 创建 Webview，负责和前端页面互相发消息

└─ webview-ui/               # Vue3 + Vite + Vue Flow

   ├─ src/views/DbView.vue

   ├─ src/views/DesignView.vue

   └─ src/views/DiffView.vue

有一个很省事的小技巧：用 `json-schema-to-typescript` 把 `tbls/spec/tbls.schema.json_schema.json` 转换成 TS 类型，这样你的代码和 tbls 的格式保证一致，tbls 升级时重新生成一次就行。

用户项目里的 workspace 结构：

<用户项目>/.harness/

├─ harness.yml               # tbls 可执行文件的路径、默认 schema、要排除哪些表

├─ design/

│  ├─ schema.json            # tbls 格式

│  └─ ext.json

└─ db/

   ├─ .tbls.yml              # 从设计模型生成：relations、comments、exclude

   └─ snapshots/<时间>.json   # tbls 导出的原始结果

## 四、开发步骤

M0 搭项目骨架（半天）

npm i -g yo generator-code @vscode/vsce

yo code          *# 选 New Extension (TypeScript)*

在 Cursor 里打开生成的项目，按 F5，在新窗口里运行 Hello World 命令，确认调试环境能跑通。

M1 读取数据库（1 到 2 天）

- 新增命令 `Harness: Sync DB`：调用 `tbls out <dsn> -t json --sort`，把结果保存到 `.harness/db/snapshots/`；
- 在侧边栏用 TreeView 显示表和字段的列表。

第一版先让用户在配置里填 tbls 的路径；以后再为每个平台打包内置的 tbls（`vsce package --target win32-x64` 可以打包指定平台的版本）。

M2 可视化 db 模块（3 到 5 天）

- Webview 里用 Vue3 + Vite + Vue Flow 渲染快照：表是节点，关系是连线，用 elkjs 自动布局；
- 实现适配器 `normalize.ts`，处理上次提到的那几个问题。用你手上的两份导出做测试数据。

M3 设计模块（1 到 2 周）

- 新建 `design/schema.json`，支持"从数据库快照导入，作为初始设计"。对已有项目来说这很实用；
- 编辑方式：先做表单（表、字段、关系），画布同步显示，以后再加拖拽编辑；
- 编辑 `ext.json` 里的关系类型、说明和分组。

M4 对比视图（1 周）

- 做 design 和 db 的结构对比：缺失、多出、不一致、已确认的偏差；
- 在同一张画布上用颜色和线型标出差异。

M5 利用 tbls 的现有能力（2 到 3 天）

- 用 `tbls doc json://design/schema.json` 生成设计模型的文档，以及 Mermaid 格式的图；
- 从设计模型生成 `db/.tbls.yml`（relations、comments、exclude），让开发模型生成的文档也带上逻辑关系；
- 接入 `tbls lint`，作为治理检查。

M6 MCP（1 周）

- 提供只读接口：获取设计模型、获取开发模型、获取差异列表、获取某一项差异的详情；
- 注册到 Cursor，让 Agent 能基于差异生成 SQL。

M0 到 M4 做完，就是一个能用的第一版，大约需要 4 到 6 周的业余时间。

## 五、需要提前注意的几点

1. Webview 和插件主进程是隔离的，两者只能通过 `postMessage` 互相发消息。读文件、调用 tbls 都在插件主进程里做，Webview 只负责显示和编辑。
2. Webview 有内容安全策略（CSP）限制。Vite 构建出来的资源路径要用 `webview.asWebviewUri` 转换，否则页面会加载不出来。可以参考微软官方的 `vscode-webview-ui-toolkit-samples` 仓库里的 Vue 示例（toolkit 本身停止维护了，但示例里的 Vite + Webview 配置方式仍然有用）。
3. 设计文件保存格式要稳定：固定表和字段的顺序，保证每次保存生成的 JSON 格式一致，这样 Git diff 才清楚可读。

需要的话，切换到 Agent 模式后，我可以帮你把 M0 的项目骨架搭起来，包括插件部分、Vue3 Webview 和 tbls 调用，直接做到 M1。
