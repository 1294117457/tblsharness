# 03 · 风险与决策记录（ADR 风格）

> ADR (Architecture Decision Record)：每个决策记录"为什么选这个 / 拒绝的替代方案 / 后果"。**评审时优先看这份**。

---

## ADR-001 · 取消看板，把能力并入 TreeView

**状态**：已批准（用户明确要求）

**背景**：画布内左侧 240px 的 `SourcePanel.vue` 与侧边栏 `TreeView` 重复表达同一份数据（设计表 / 设计图 / 数据库），且占空间。

**决定**：删除 `SourcePanel.vue`，把能力迁到 `harness.workspaces` 视图的 TreeView。

**考虑过的替代方案**：

| 替代方案 | 为什么放弃 |
|:--|:--|
| 把看板缩为 32px 竖条 | 用户要求**取消**，不是缩小 |
| 重写为侧边栏 `WebviewView` 自定义 HTML 渲染 | 工作量 5+ 天；VS Code `WebviewViewProvider` API 与现有 `CustomEditor` 边界未摸清；当前 TreeView 的 `iconPath` + `description` 配合 `view/item/context inline` 组已能满足 inline 按钮 |
| 只搬导出按钮，保留看板其它能力 | 用户原话明确要求**取消**看板 |

**后果**：

- 画布宽度从 `1920 - 360 = 1560px` 增到 `1920 - 60 = 1860px`
- 用户在 TreeView 多两步操作（点开 design 节点 → 点 db 段）才能看到 db 表，但少一次 240px 看板认知负担

## ADR-002 · TreeView 树结构改为 `design / {tables, diagrams, db, partitions}`

**状态**：已批准

**背景**：当前 `workspace / {design, db}` —— 顶层有两个组："设计画布"和"数据库"。

**决定**：db 全部移入 design 之下。workspace 顶层只剩 `workspace / design / {tables, diagrams, db, partitions}` 四段。

**考虑过的替代方案**：

| 替代方案 | 为什么放弃 |
|:--|:--|
| workspace 顶层保留"数据库"组 + design 下重复显示 | 用户原话"数据移入设计画布下"明确要求 |
| workspace 顶层保留"数据库"组 + design 下不显示 | 同一个 db 多次引用关系难表达 |

**结果**：

- `tree.ts` 的 `TreeNode` 类型删除 `group` / `placeholder` 两种节点
- `db` 节点加 `design: string` 字段
- `levelGroup` 的 `group` 字段扩展为 `'tables' | 'diagrams' | 'db' | 'partitions'`
- `getChildren(workspace)` 直接列 design，不再列 group

**关键决策**：db 在两个 design 下重复出现 = 正常。**不**做"已添加"去重。

## ADR-003 · 用 TreeView inline 按钮替代看板的复选框

**状态**：已批准（用户拍板 `webview-view`，后改 `panel-gone-lite`）

**背景**：看板的 `onCanvas` 复选框行为是核心交互之一。

**决定**：在 `package.json contributes.menus.view/item/context` 加 `inline` 组，靠右键菜单的小图标按钮触发显示/隐藏。

**考虑过的替代方案**：

| 替代方案 | 为什么放弃 |
|:--|:--|
| `TreeItemCheckboxState` + `when` | 只能在 `when` 表达式里用，**不能**让用户点击切换 |
| 侧边栏 `WebviewView` 渲染真 checkbox | 工作量 5+ 天（见 ADR-001） |

**结果**：

- 新增命令 `harness.item.toggleHidden`（处理表 / 设计图 / db 表的 hidden 状态）
- 新增命令 `harness.diagram.toggleHidden`（语义更清晰，**推荐**）
- `package.json` 加 4 个 inline 菜单项 + 3 个新命令定义

**简化**：本轮不做 `$(eye)` / `$(eye-closed)` 双态切换（VS Code 的 icon 取决于当前 hidden 状态读 `TreeItem.description` 里加后缀"已隐藏"提示用户）。

## ADR-004 · db 表默认勾选 = `onCanvas`（不是"未勾"）

**状态**：已批准（用户拍板 `add-to-root`）

**背景**：看板现在的"勾选"语义有两层：① `onCanvas`（画布上有 node）② `shown`/`hidden`（在当前层可见）。

**决定**：TreeView 的复选框（其实是 inline eye 按钮）= `onCanvas` 状态的"显示/隐藏"切换。**默认行为 = 当前 hidden 状态的反向**。

**结果**：

- 用户看到的"在画布上有 node 但 hidden"的表：能直接点 eye 按钮让它显示
- 用户看到"画布上没有 node"的 db 表：点按钮 = 加到根画布（**不**加到 design 表）

**注意**：TreeView 行的 `description` 末尾要加 ` · 已隐藏` 提示，**不**在 icon 上做双态（VS Code TreeView icon 是单态）。

## ADR-005 · 新增 `harness.db.addToDesign` 命令

**状态**：已批准

**背景**：TreeView 的"➕ 添加数据库"按钮（design 下"数据库"段的占位 placeholder）需要触发"加 db 到 design 引用"。

**决定**：新增 `harness.db.addToDesign` 命令，直接写 `meta.sources` + `store.invalidate`，**不**走 `canvasEditor.addDbSource` webview 协议。

**考虑过的替代方案**：

| 替代方案 | 为什么放弃 |
|:--|:--|
| 必须先 `harness.design.open` 打开画布，激活态下走 webview 协议 | 强制打开画布对 TreeView-only 工作流是负担 |
| 复用现有 `harness.source.addToCanvas` | 现有命令是"加 db + 加表"混合，看板新流程只需要"加 db" |

**结果**：

- `canvasEditor.ts:1131` 的 `addDbSource` webview 内部方法**保留**（画布内 `+ 添加数据库` 还在用）
- `harness.db.addToDesign` 是新入口，处理 TreeView-only 路径
- `store.invalidate` 触发所有打开画布的 `pushSources`（`canvasEditor.ts:1006-1015` 那段），用户**会**在画布里看到新 db

## ADR-006 · 移除看板但保留 `addDbTables` / `removeDbTables` 函数

**状态**：已批准

**背景**：`App.vue:373`（右键菜单"添加关联的表"）和 `App.vue:762`（Inspector "显示关联的表"）**还在用** `addDbTables`。

**决定**：`SourcePanel.vue` 移除，但 `addDbTables` / `removeDbTables` 函数**保留**。它们是"加 db 表到画布"的通用接口，跟看板无关。

**结果**：

- `App.vue:205 / 230` 不删
- `App.vue:373 / 762` 不改
- 移除的只有 `<SourcePanel>` 模板引用

## ADR-007 · 删除 `levelContent.db` / `dbElsewhere` 字段

**状态**：已批准

**背景**：`levelContent` 返回 4 个字段：`tables` / `diagrams` / `db` / `dbElsewhere`。后两个**只在看板里用**。

**决定**：删除 `db` / `dbElsewhere` 字段，保留 `tables` / `diagrams`（被画布右键菜单用）。

**结果**：

- `viewModel.ts:118-120` 接口精简为 2 字段
- `viewModel.ts:140-148` 函数体精简
- `App.vue:55` 的 `levelLists = computed(() => levelContent(view.value, state.level))` **保留**（`tables` / `diagrams` 还在用）

## ADR-008 · 不引入新依赖

**状态**：已批准

**背景**：本轮有 4 个候选方案（侧边栏 WebviewView / TreeView 重排 / WebviewView 自定义 tree / 看板缩竖条）。

**决定**：**只用**现有依赖。**不**引入 `webviewview-panel` / `react-window` / 任何状态管理库。

**结果**：

- `package.json` dependencies / devDependencies **不变**
- 编译产物大小不变
- 风险面：零

---

## ADR-009 · 不重写为 side panel 树

**状态**：已批准

**背景**：候选方案里有"用 WebviewView 渲染自己的树"。

**决定**：**不**做。本轮目标是把看板"融合到"现有 TreeView，而不是另起炉灶。

**后续**：如果 0.0.6 用户反馈 inline 按钮体验仍不够（比如要 checkbox 多选），**0.0.7 再考虑**重写为 side panel webview view。

## 风险登记

| 风险 | 概率 | 影响 | 缓解 |
|:--|:--:|:--|:--|
| TreeView 重排后某条命令的 `arg.kind` 推断与新结构不匹配 | 中 | 高 | 实施时 `commands/*.ts` 全部过一遍；`@argument` 类型如果改就 `commands/common.ts:42-51` 的 `NodeArg` 同步 |
| inline 按钮的 `when` 表达式没生效 | 低 | 中 | `package.json` 加 `view == harness.workspaces` + `viewItem =~ /.../` 兜底 |
| `meta.sources` 写入后打开的画布**没**看到新 db | 低 | 高 | 走 `store.invalidate` 让 `canvasEditor` 重新推 sources；测试覆盖 |
| 用户失去搜索框 | 中 | 低 | VS Code 原生 `Ctrl+F` 覆盖；写进 0.0.6 release notes |
| 设计图（diagram）inline 按钮误触发"删除" | 低 | 高 | inline 按钮只触发"显示/隐藏"，**不**用 `$(trash)` 图标 |
| 看板拿掉后老用户升级找不到"添加数据库" | 中 | 中 | 0.0.6 release notes 写明；TreeView 的 db 段有占位 placeholder |
| 工作量低估 | 中 | 中 | 计划 2 工作日；预留 0.5 天 buffer |
