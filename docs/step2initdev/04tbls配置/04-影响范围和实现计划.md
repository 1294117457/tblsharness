## 二、目录结构示意

```
<globalStorage>/                                       ← context.globalStorageUri
├─ tbls.current.json                                   ← 指向当前启用的 tbls 二进制
├─ releases-cache.json                                 ← 缓存的 latest release 元数据 (TTL 1 天)
└─ bin/
   ├─ tbls-1.96.0-windows-amd64/
   │  └─ tbls.exe
   ├─ tbls-1.96.0-darwin-arm64/
   │  └─ tbls
   └─ tbls-1.95.0-windows-amd64/                      ← 旧版本（最多保留 5 个）
      └─ tbls.exe
```

`tbls.current.json` 损坏 / 缺失 → `ensureTbls` 重置并重新下载。

## 四、调用方改动

### 4.1 `db.ts#harness.db.sync`

现在：

```ts
const tblsPath = config.get<string>('tblsPath', 'tbls') || 'tbls';
// ...
const result = await tblsOutJson({ tblsPath, ... });
```

改为：

```ts
const configured = config.get<string>('tblsPath', '') || '';
const { path: tblsPath, source } = await resolveTblsPath(h.context, configured);
if (source === 'missing') {
  // ensureTbls 失败，引导用户
}
// ...
const result = await tblsOutJson({ tblsPath, ... });
```

### 4.2 `connectionPanel.ts#runTbls`

同样的 `resolveTblsPath` 调用，把 `tblsPath` 和 `source` 一起塞进 `init` 消息。

### 4.3 错误的 action 字段

`runner.ts` 的 `TblsError('notFound', '...')` 路径不变；`connection/errors.ts` 识别后返回：

```ts
{ message: '找不到 tbls 可执行文件。', action: 'setTblsPath' | 'downloadTbls' }
```

`setTblsPath` 用于"用户已经手动配置过路径但找不到"的情况（走原来的"设置 tbls 路径"按钮）。
`downloadTbls` 用于"内置版本也没下下来"的情况（走四个按钮的引导）。

## 五、连接页面 UI 改动

表单底部"名称"行下面加一行：

```
  tbls：v1.96.0（内置版本）  [管理 tbls…]                  ← 状态 + 跳转设置
```

或：

```
  tbls：未配置  [下载内置版本] [选择本地文件…]              ← 缺失时
```

`[管理 tbls…]` 跳到设置 `harness.tblsPath`（点击自动聚焦）。
`[下载内置版本]` 调 `harness.tbls.repair`，下载完成后状态行更新。
`[选择本地文件…]` 弹文件选择框，写入 `harness.tblsPath`。

设计原则：**状态只显示，不阻塞**。如果 tbls 缺失，点击"测试连接"才报错；状态行只是预告。

## 六、命令注册

`src/commands/tbls.ts`：

```ts
export function registerTblsCommands(h: Harness): void {
  register(h, 'harness.tbls.checkUpdate', async () => {
    const info = await checkUpdate(h.context);
    if (!info.hasUpdate) { vscode.window.showInformationMessage(`当前已是最新版本（${info.current}）。`); return; }
    const pick = await vscode.window.showInformationMessage(`tbls ${info.latest} 可用（当前 ${info.current}）。是否下载并启用？`, '下载并启用', '稍后');
    if (pick === '下载并启用') await applyUpdate(h.context, info);
  });

  register(h, 'harness.tbls.repair', async () => {
    await repair(h.context);
    vscode.window.showInformationMessage('已重新下载 tbls。');
  });

  register(h, 'harness.tbls.openFolder', async () => {
    await vscode.env.openExternal(vscode.Uri.file(h.context.globalStorageUri.fsPath + '/bin'));
  });
}
```

## 七、单元测试目标

`test/tbls.test.ts`：

- ✅ `pickAsset(platform, arch, version)` 对 5 种主流组合返回正确 asset 名
- ✅ `pickAsset` 对不支持的组合（`linux ia32`、`freebsd` 等）返回 `undefined`
- ✅ `verifySha256(buffer, sha256)` 正确
- ✅ `parseReleaseAssets(releaseJson, target)` 找出对应 `browser_download_url` 和 `digest`
- ✅ `parseReleaseAssets` 在 release 不含目标 asset 时返回 `undefined`
- ✅ `maskSecret` 现有测试保留并增加新用例（包含多行 / 包含 base64 编码的密码）

集成测试（手工 / 调试模式下跑）：

- ☐ 全新环境 + 有网：首次激活后 `bin/` 出现对应平台的 tbls 二进制
- ☐ 全新环境 + 断网：右下角通知"下载失败"，连接时报错走四个按钮
- ☐ 已有内置版本 + 用户改了 `harness.tblsPath`：直接用用户的，不重复下载
- ☐ 用户执行 `harness.tbls.checkUpdate` + 真有新版本：弹窗 + 下载 + 切换
- ☐ macOS ARM64 / Windows x64 / Linux x64 三种都跑通
- ☐ `harness.tblsPath = "tbls"`（老默认）时的兼容路径

## 九、不做的事（明确划出）

1. **不做** tbls 的"自动后台静默更新"——升级通过 `harness.tbls.checkUpdate` 按钮触发。
2. **不**修改用户机器的 `PATH` / 不安装到系统目录——所有二进制都在 `globalStorage/bin/`。
3. **不**做"按 .tbls.yml 自动下载外部驱动"——这是 [03-tbls-capability.md](../02新增设置/03-tbls-capability.md) 提到的扩展机制，不在本范围。
4. **不**改 `runner.ts` 的 `execFile` 逻辑（不感知"内置版本"）——判断在哪一层做是 §四的约定。
5. **不**改 `harness.db.sync` 的其它行为（进度通知、超时、缓存）；只在 `tblsPath` 来源上换实现。
6. **不**新增单独的"下载面板"或"管理 UI"页面；状态显示放在连接页面，命令入口放在命令面板。
7. **不**处理 "tbls 下载后用户改了路径又改回来" 的边缘情况——以 `tbls.current.json` 为准，用户改路径是覆盖内置版本，不需要特殊处理。

## 十、实施顺序（建议）

1. **第一步：把 `runner.ts` 的调用统一到 `resolveTblsPath`**（`src/tbls/resolver.ts`）。这一步先把"路径怎么来"封装起来，但**内部仍按 `config.get('tblsPath')` 走**，行为完全不变。好处：后面的改动只需要改 `resolver.ts`。
2. **第二步：实现 `manager.ts` 的 `ensureTbls`、`probe`、`readCurrent`，加单元测试**。**不**立刻接 `activate`，先用命令 `harness.tbls.repair` 触发，验证下载 / 校验 / 放置流程。
3. **第三步：接到 `activate`，把 `resolveTblsPath` 升级为"内置优先 + 用户路径覆盖"**。
4. **第四步：连接页面 UI 状态行**。
5. **第五步：`harness.tbls.checkUpdate`**。
6. **第六步：设置面板"浏览…"按钮**（`harness.tblsPath` 描述 + 贡献 `when`）。
7. **第七步：兜底四个按钮 + 错误 action 字段**。
8. **第八步：跑手工 / 集成测试**（macOS ARM64 / Windows x64 / Linux x64），更新文档。

每一步完成后跑 `typecheck` / `test` / `build`。
