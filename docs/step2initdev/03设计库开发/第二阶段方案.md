# 设计库第二阶段方案：合并为"设计画布"，画布分区，其他设计图

> 前置文档：`设计库初步优化.md`（整体方案）、`第一阶段完成说明与第二阶段方案.md`（第一阶段结果）。
> 本文**替代**上一份文档第五节的第二阶段方案：先改架构，再做原计划的设计图内容。
> 日期：2026-09-29。代码路径相对于 `harness-cursor/`。已有数据都是测试数据，**不做迁移**，旧格式直接不再读取。
>
> **已确认**（2026-09-29）：1. 名称叫"设计画布"；2. 分区默认只管摆放；3. 第一张画布默认显示全部设计表，之后新建的画布默认为空；4. 第一版不支持分区嵌套。

## 一、结论

1. **取消独立的"画布"和"设计库"两个概念，合并为"设计画布"**。一个设计画布 = 一份表结构 + 若干张画布 + 若干张设计图 + 引用的数据库。画布从工作区一级移到设计画布里面，只属于这一个设计画布。
2. **一个设计画布可以有多张画布**，同一份表结构放在不同画布里看不同的部分。每张画布里可以有多个**分区**，把表按业务分块摆放。
3. **不需要设计时也用同一套东西**：设计画布的表结构可以是空的，画布上只放数据库里的表，就是一个"看数据库"的画布。
4. **一张画布只对应一个设计画布**。以后提供"设计画布之间复制粘贴表"的功能，替代"一张画布放多个设计库"。
5. 数据库（连接、凭据、快照）**仍放在工作区一级**，多个设计画布可以引用同一个数据库，不用重复填连接。
6. 工作分三步：**A. 架构合并**（本阶段的主体）→ **B. 补第一阶段遗留**（表改名同步设计图等）→ **C. 其他设计图**（状态图、流程图等，原第二阶段内容）。

## 二、概念与命名

| 概念 | 说明 | 界面名称 |
| :-- | :-- | :-- |
| 工作区 | 组织多个设计画布和数据库 | 工作区 |
| 设计画布 | 一份表结构 + 画布 + 设计图 + 引用的数据库。原"设计库" | 设计画布（默认名"设计画布 1"） |
| 表结构 | 设计画布自己的表，tbls 格式 `schema.json`，可以为空 | 表结构 |

```
工作区 1
├─ 设计画布
│  └─ 设计画布 1
│     ├─ 画布（2）          画布 1、画布 2 —— 点击打开
│     ├─ 表结构（12 张表）  → 表 → 字段
│     ├─ 设计图（3）
│     └─ 数据源（1）        host:5432/app —— 点击在树中定位到数据库
└─ 数据库
   └─ host:5432/app        → 表 → 字段（连接、同步、快照，和现在一样）
```

- 点击"设计画布 1"本身：打开最近用过的画布（没有记录时打开第一张）。
- 新建设计画布时自动带一张画布"画布 1"（`designTables: all`），和现在新建工作区自带画布一样。
- 工作区下的"画布"分组去掉。

## 三、存储结构

```
<存储目录>/workspaces/<workspaceN>/
├─ workspace.yml                     name, description, seq:{design, db}
├─ design/<designN>/
│  ├─ design.yml                     name, description, sources:[dbN…], seq:{canvas, diagram}, lastCanvas
│  ├─ schema.json                    表结构（tbls 格式，可以没有表），模块存在 viewpoints
│  ├─ ext.json                       关系类型等 tbls 表达不了的信息（不变）
│  ├─ comparisons.json               与各数据库的对比设置：{ [dbN]: { tableMappings, acceptedDiffs } }
│  ├─ canvases/<canvasN>.json        画布（新格式，见下）
│  └─ diagrams/<diagramN>.md         设计图（不变）
└─ db/<dbN>/                         不变：source.yml、.tbls.yml、snapshots/
```

变化：

- `source.yml` 改名为 `design.yml`，增加 `sources`（引用的数据库 ID 列表）、`seq.canvas`、`lastCanvas`。**只存 ID**，不存数据库显示名（含主机）。
- 工作区一级的 `canvas/` 和 `comparisons.json` 删除，对比设置移到各设计画布里。
- 删除数据库时：从所有设计画布的 `sources`、画布节点、`comparisons.json` 中清掉它，删除前的确认框列出受影响的设计画布。

### 3.1 画布文件（version 2）

```jsonc
{
  "version": 2,
  "name": "画布 1",
  "description": "订单相关",
  "designTables": "picked",            // all：本设计的表全部显示（新表自动出现）；picked：只显示 nodes 里的
  "nodes": [
    { "source": "design", "table": "orders", "x": 0, "y": 0, "zone": "z1" },
    { "source": "db1", "table": "public.orders", "x": 320, "y": 0, "display": "keys" }
  ],
  "zones": [
    { "id": "z1", "name": "订单", "color": "#4a90d9", "x": -40, "y": -60, "width": 800, "height": 500, "viewpoint": "订单" }
  ],
  "notes": [],
  "comparison": { "db": "db1", "mode": "overlay" },
  "settings": { "columnDisplay": "all" },
  "viewport": { "x": 0, "y": 0, "zoom": 1 }
}
```

- 节点的 `source` 是 `"design"`（本设计）或数据库 ID（`db1`），**去掉现在的别名（`d1`/`b1`）**。节点 ID 变成 `design/orders`、`db1/public.orders`。
- 画布上用哪些数据库由设计的 `sources` 决定，画布里不再有 `sources` 列表；数据库的表只能挑选放入（没有"全部"模式）。
- `comparison` 只需要选数据库，设计一侧固定是本设计。
- 分区用 `zones`，节点用 `zone` 标明属于哪个分区；坐标一律是画布绝对坐标（分区移动时一起移动里面的节点）。

## 四、画布

### 4.1 界面

```
┌ 工具栏：画布名 | 画布切换 ▾ | + 新建表 | + 分区 | + 便签 | 自动布局 | 字段显示 | 对比：[不对比 ▾] ┐
├ 左侧面板 ──────────┬ 画布 ───────────────────────────────┬ 右侧面板 ────────────┤
│ 本设计（12）        │  ┌ 订单 ───────────────┐              │ 属性 | 差异 | 待同步 | 设计图 │
│  ☑ orders           │  │ orders   refunds    │  ┌ 用户 ┐    │                      │
│  ☐ refunds          │  └─────────────────────┘  │users │    │                      │
│ 数据源               │                           └──────┘    │                      │
│  host:5432/app  ⟳   │                                        │                      │
│   ☐ public.orders   │                                        │                      │
│  + 添加数据库…      │                                        │                      │
│ 分区                 │                                        │                      │
│  订单（2）· 用户（1）│                                        │                      │
└─────────────────────┴────────────────────────────────────────┴──────────────────────┘
```

- **画布切换**：下拉列出本设计的所有画布，选择后打开那张画布（每张画布一个编辑器页签，撤销、保存逻辑和现在一样）。下拉里还有"新建画布""复制当前画布"。
- **左侧"本设计"**：勾选表放到画布上 / 从画布移除；顶部开关"显示全部表"对应 `designTables: all`。
- **左侧"数据源"**：列出本设计引用的数据库和它们的表，勾选放入画布（只读节点，样式和现在的数据库表一致）。"+ 添加数据库…"可以选择工作区里已有的数据库，或者直接打开连接页面新建一个，成功后自动加入本设计的 `sources`。
- **右侧"设计图"页签**：列出本设计的设计图，点击打开；选中表时只列出引用这张表的设计图，并提供"新建与这张表相关的图"（C 步骤）。

### 4.2 分区

- **新建**：工具栏"+ 分区"在视口中央放一个空分区；框选若干表后右键"放入新分区"，分区自动包住这些表。
- **归属**：把表拖进分区框内松开 → 加入该分区；拖出 → 移出。一张表在一张画布上只属于一个分区（或不属于任何分区）。
- **移动 / 大小**：拖动分区标题栏整体移动（里面的表一起动）；拖边角改大小；"适应内容"按钮把框收到刚好包住里面的表。
- **自动布局**：先在每个分区内部排布，再把分区和未分区的表作为整体排布（elkjs 的层级布局）。
- **删除分区**：只删框，里面的表留在原处。
- **分区和模块（viewpoints）**：分区可以"设为模块"，这时 `viewpoint` 字段记下模块名：
  - 分区里**本设计的表**就是这个模块的表，写入 `schema.json` 的 `viewpoints`（`tbls doc` 会为它生成单独的文档页）；
  - 数据库的表不进模块（模块只描述设计）；
  - 分区改名 → 模块改名；删除分区时询问是否同时删除模块；
  - 另一张画布上可以放一个绑定同一模块的分区，它的设计表列表以 `viewpoints` 为准，两张画布保持一致。
  - 没"设为模块"的分区只是画布上的摆放，不影响表结构。

### 4.3 数据库的表复制到设计

数据库表节点右键"复制到设计"（可以多选）：

- 复制字段（类型、可空、默认值、注释）、主键、唯一约束、索引、表注释；
- 选中的表之间、以及和设计中已有同名表之间的外键一起复制成关系；
- 表名已存在时提示：跳过 / 改名为 `xxx_2`；
- 复制后在旁边放上新的设计表节点，可以撤销。

这替代现在的"从数据库复制新建设计库"。新建设计时仍可以选"从数据库复制全部表"，内部就是新建空设计 + 引用该数据库 + 复制全部表。

### 4.4 对比

工具栏"对比"只选数据库（本设计引用的）。规则、标记、确认偏差和现在一样，只是 `comparisons.json` 在设计目录里、按数据库 ID 分开存。

## 十、已确认 / 待确认

**已确认**：

1. **名称**：叫"设计画布"（默认名"设计画布 1"）。
2. **分区和模块**：分区默认只管摆放，需要时手动"设为模块"。
3. **设计表的默认显示**：新设计画布的"画布 1"默认显示全部设计表（`designTables: all`），之后新建的画布默认为空（`designTables: picked`），从左侧挑选。
4. **分区嵌套**：第一版不支持。

**C 步骤开工前再定**：

5. 枚举存在哪里：建议 PostgreSQL 用 `schema.enums`，MySQL 用字段类型 `enum(...)`，其他库存在 `ext.json`。
6. 流程图 / 时序图怎么认出表：建议数据流图的 `[(orders)]` 和时序图里与表名相同的参与者表示表。
7. 表改名后替换 Mermaid 正文：建议默认勾选。
8. 设计图编辑器撤销：建议保留最近 10 次（已写入第六节）。
