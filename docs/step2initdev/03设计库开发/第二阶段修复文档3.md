# 第二阶段修复文档 3

> 前置：`第二阶段修复文档2.md` 问题五（可嵌套的分区画布）已实现。本文档调整它的**交互方式**：显示区域始终是一张设计画布，不再"进入"某一层，也不再为设计图单独开标签页。数据结构（`layout.json` v3、命名空间、复制 / 剪切）不变。
>
> 对比功能（设计 vs 数据库）本次不动，第三阶段再做。

---

## 0. 总体原则

1. **显示区域不脱离设计画布**。分区画布就是画布上的一块区域（嵌套框），设计图就是画布上的一张卡片，表就是画布上的节点。任何操作都不切换成"另一个页面"，也不打开新标签页。
2. **点击 = 选中，聚焦按钮 = 把视图对准它**。选中的对象右上角出现一个聚焦按钮 `⤢`，点击后画布平移缩放到这个对象，其他内容仍然在画布上（只是移出了视野）。
3. **右侧面板跟随选中的对象**。选中设计表 → 编辑表；选中设计图 → 编辑 Mermaid 文本；选中数据库表 → 查看表结构；选中分区画布 → 编辑分区。

## 问题一：新建 / 点击分区画布会切换到另一个页面

### 1.1 现状

问题五实现了"层级（scope）"：画布同一时间只显示**某一层及其子分区**。以下操作都会切换层级，看起来就像跳到了另一个页面（新建的分区是空的，所以切过去是一片空白）：

| 入口 | 现在的行为 |
| :-- | :-- |
| 树上点击分区画布节点 | `harness.partition.open` → `setScope(partN)`，画布只剩这个分区 |
| 树上"分区画布"分组的 +，新建后点击新节点 | 同上 |
| 画布上双击分区框标题 / 点击框上的 ↗ / 右键"进入这个分区画布" | `setScope(partN)` |
| 面包屑 | 在层级之间切换 |
| `Esc` | 回到上一层 |

画布工具栏"+ 分区画布"本身不切层级，会在当前层的视图中央放一个空框。但如果当前已经"进入"了某个分区，新框只在那个分区里可见，根画布看不到全貌。

### 1.2 期望

- 分区画布**始终是根画布上的一块区域**，打开设计画布时看到的就是整张根画布，所有分区框按嵌套关系显示。
- 新建分区画布 = 在画布上加一个框，视图不跳转；新框自动选中，右侧面板显示它的名称、说明、命名空间。
- 想看某个分区的细节 → 选中后点聚焦按钮（见问题三），视图缩放到这个框。

### 1.3 方案：去掉"层级切换"，改为"聚焦"

| 原来（scope） | 改为（focus） |
| :-- | :-- |
| 画布只渲染当前层及其子分区 | **总是渲染整张根画布**（所有层） |
| 切换层级 = 换一批节点，恢复该层视口 | 聚焦 = 不换节点，只把视口 `fitBounds` 到目标对象 |
| 每层单独记视口 `viewports[partN]` | 只记一个视口 `viewports.root`；其他键读到后忽略，下次保存时去掉 |
| 面包屑 = 当前层路径，点击 = 切层级 | 面包屑 = **当前层**的路径（见 1.4），点击 = 聚焦那个分区框；点根 = 适应整张画布 |
| 双击分区框标题 = 进入 | 双击分区框标题 = 聚焦这个框（和聚焦按钮一样） |
| 树上点击分区画布 = 进入 | 树上点击分区画布 = 打开设计画布（已打开就激活标签页）+ 选中并聚焦这个框 |
| `Esc` = 回上一层 | `Esc` = 先取消选中；没有选中时聚焦到上一层的框（到根就适应整张画布） |

折叠的分区框仍然保留（`collapsed`）：聚焦一个折叠的框时自动展开它（作为一次可撤销的布局编辑）。

### 1.4 "当前层"还有什么用

画布不再切换，但"当前层"这个概念还需要保留，用在两个地方：

1. **左侧数据源面板**只列当前层的设计表 / 设计图 / 数据库表（问题五 5.6 的规则不变）。
2. **工具栏新建**（新建表、+ 设计图、+ 分区画布、+ 便签）放到当前层。

3. **画布上粘贴**（`Ctrl+V`、工具栏 / 右键"粘贴"）放到当前层（见 1.5）。

当前层的确定规则：

| 操作 | 当前层变成 |
| :-- | :-- |
| 选中 / 聚焦一个分区框 | 这个分区 |
| 选中 / 聚焦一张表、设计图、便签 | 它所在的层 |
| 点击画布空白处（不在任何框里） | 根画布 |
| 点击某个框内的空白处 | 这个框 |
| 面包屑点击 | 那一层 |

- 面包屑一直显示当前层路径，例如 `商城设计 › 订单 › 支付`，让用户知道左侧列表和工具栏新建是针对哪一层。
- 工具栏新建的位置：如果视口中心落在当前层的框内，就放在视口中心；否则放在当前层框内的空位（框自动撑大）。
- 右键菜单、双击空白 / 框内新建的规则不变（本来就是按鼠标位置所在的框）。

### 1.5 复制 / 剪切 / 粘贴：粘贴到当前层

复制和剪切可以从**任意层**选对象（画布上多选、树上多选都行，跨层也可以）；**粘贴时聚焦在哪一层，就粘贴到哪一层**。

| 项目 | 规则 |
| :-- | :-- |
| 粘贴目标 | 画布上：当前层（1.4）。树上：右键的那个节点所在的层（树上有明确的目标，不变） |
| 粘贴位置 | 鼠标在当前层的区域内（根画布，或当前分区框内且不在它的子分区框里）→ 放在鼠标位置；否则放在当前层框内的空位（框自动撑大） |
| 粘贴后 | 选中粘贴出来的对象，当前层不变 |
| 命名 / 外键 / 命名空间 | 不变，按修复文档 2 决定 3、决定 9（`_copy`、换命名空间、副本内部外键指向副本） |
| **数据库表** | 原来复制时跳过（修复文档 2 偏差 7）。改为：复制数据库表 → 粘贴 = **复制成设计表**（复用 `table/copyToDesign` / `copyTableOps`，字段、主键、注释、关系一起复制），放到当前层，自动补当前层的命名空间，重名按 `_copy` 规则。剪切数据库表不支持（数据库表不属于设计），剪切时提示"数据库表只能复制" |
| 混合选择 | 一次复制里同时有设计表、设计图、分区画布、数据库表时，一起粘贴到当前层；数据库表按上一行转换成设计表 |

原来画布粘贴按"选中的框 → 鼠标下的框 → 当前层"的顺序找目标，改为统一用当前层，避免"粘贴到哪里"不可预期。想粘贴到某个分区里：先点一下那个框（或框内空白），它就成了当前层。

### 1.6 需要注意

- **渲染量**：嵌套多、设计图卡片多时整张画布一起渲染会变慢。处理：开启 Vue Flow 的 `onlyRenderVisibleElements`（只渲染视野内的节点）；Mermaid 卡片离开视野后保留上次渲染的 SVG，不重复渲染。
- **自动布局**：原来"自动布局"只排当前层；改为：没有选中时排整张画布（`layoutLevel(根)`，多层复合节点），选中了分区框时只排这个框的内部。

## 问题二：新建设计图直接放在画布上，Mermaid 文本在右侧编辑

### 2.1 现状

| 入口 | 现在的行为 |
| :-- | :-- |
| 画布工具栏"+ 设计图 ▾"、右键"新建设计图" | 放卡片，不开标签页（问题五已做到） |
| 树上"设计图"分组的 +、右键"新建设计图" | 放卡片，**并打开设计图编辑器标签页** |
| 树上点击设计图节点 | 打开设计图编辑器标签页 |
| 画布上双击设计图卡片、右键"打开"、属性面板"打开编辑" | 打开设计图编辑器标签页 |

画布上的卡片只能看，改 Mermaid 必须去另一个标签页。

### 2.2 期望

- 新建设计图 = 在**当前层**的画布上加一张卡片，自动选中，右侧面板直接显示它的 Mermaid 文本，光标放进文本框，可以马上输入。
- 在右侧改文本，画布上的卡片**实时**重新渲染（防抖 300ms）。
- 树上点击设计图 = 打开设计画布，选中并聚焦这张卡片，右侧显示文本。不开新标签页。

### 2.3 右侧面板：设计图

```
设计图                                   [⤢ 聚焦]
名称  [订单状态图            ]
类型  状态图                说明 [            ]
┌ Mermaid ─────────────────────────────────────┐
│ stateDiagram-v2                              │
│   [*] --> 待支付                              │
│   待支付 --> 已支付                            │
│   ...                                        │
└──────────────────────────────────────────────┘
⚠ 第 3 行：无法识别的写法 ...          ← 解析错误（卡片上也显示）
[复制给 AI]  [隐藏]  [删除…]   更多 ▾（以文本打开 / 在单独标签页打开）

── 与表结构的差异（仅 ER 图）──────────────────
☑ 新增表 payments      ☐ 删除字段 orders.memo …
[应用选中项]  [忽略]
```

- **文本框**：等宽字体、显示行号、Tab 缩进；ER 图的解析错误按行号提示（复用 `parseErDiagram` 的行号）。其他类型的语法错误由 Mermaid 渲染报错，显示在文本框下方和卡片上。
- **名称 / 说明**：改 frontmatter 的 `name` / `description`，树同步更新。
- **ER 图差异**：只显示**这张图**的待同步项，复用 `SyncPanel.vue`，行为和现在的"待同步"页签一样（应用走画布撤销栈）。这是 ER 图和表结构之间的同步，不是第三阶段的"数据库对比"，所以保留。
- **单独标签页**：原来的设计图编辑器（`harness.diagram`）不删除，只从主流程里拿掉，放到"更多 ▾"和树的右键菜单里，适合大段编辑或 AI 直接改 `.md` 文件时使用。两边改的是同一个文件，互相同步。

### 2.4 文本的保存和撤销

| 问题 | 做法 |
| :-- | :-- |
| 写到哪里 | 新消息 `diagram/code {diagram, code}` → `DiagramService.modify(ref, f => ({...f, code}))`。设计图文件已经在别的标签页打开时改那个文档，否则直接写盘（和现在同步 `refs` 的方式一样），画布不会变成"未保存"。 |
| 回显 | 写完后主进程推 `diagrams`（卡片刷新）和 `pendingSync`（ER 图差异刷新）。右侧文本框正在编辑时，不用主进程推回来的文本覆盖光标位置（按"上次发送的文本"去重，和现在的设计图编辑器一样）。 |
| 撤销 | 文本框里的 `Ctrl+Z` 只撤销文字输入（文本框自己的撤销），**不进画布撤销栈**，避免每敲一个字就多一条画布撤销记录。画布上的 `Ctrl+Z` 仍然撤销布局和表结构编辑。 |
| 外部修改 | 文件被 AI 或其他标签页改了：文本框没有焦点时直接更新；有焦点时在文本框上方提示"文件已在别处修改  [重新载入]"。 |

> 需要实测：VS Code 自定义编辑器里，焦点在 Webview 的文本框时 `Ctrl+Z` 会不会被编辑器的撤销命令拦截。如果会，文本框需要自己维护一个撤销栈（拦截 `Ctrl+Z / Ctrl+Y`）。

### 2.5 各入口改为

| 入口 | 改为 |
| :-- | :-- |
| 工具栏 / 右键新建设计图 | 放卡片到当前层 → 选中 → 右侧文本框获得焦点 |
| 树上新建设计图 | 打开设计画布（没打开就打开）→ 同上。**不再**打开设计图标签页 |
| 树上点击设计图 | 打开设计画布 → 选中 + 聚焦卡片 → 右侧显示文本 |
| 双击卡片 | 选中 + 右侧文本框获得焦点 |
| 新建 ER 图时"从表结构生成"的选择 | 保留（仍然是 VS Code 的快速选择框），生成后同上 |

### 3.2 细节

| 项目 | 说明 |
| :-- | :-- |
| 按钮位置 | 右上角，节点外侧偏移几像素，不遮挡标题；分区框放在标题栏右端（替代现在的 ↗） |

| 其他对象 | 聚焦时不隐藏、不变淡其他对象（它们只是在视野外）。如果需要"只看这个分区"的效果，可以在后续加"淡化其他内容"开关 |
