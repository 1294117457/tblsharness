# 第二阶段开发文档：工作区、数据源与画布

## 一、这一阶段要解决什么

第一阶段的插件骨架（`harness-cursor/`）已经能跑通"连接数据库 → 同步结构 → 在画板里查看 → 和设计模型对比"。但使用下来有三个问题：

1. **开发体验差**：Webview 改一行代码要重新构建、再手动刷新，没有热更新。
2. **必须先连数据库**：侧边栏一打开就要求设置数据库连接，而很多时候用户是在项目早期、还没有数据库时就想开始设计模型。
3. **一个项目只有一套固定的"设计模型 + 数据库"**：没法同时维护多个设计版本或多个数据库（比如测试库和生产库），也没法只挑一部分表出来画一张专题图。

这一阶段的目标：

| 目标 | 说明 |
| :-- | :-- |
| Webview 热更新 | 修改 `.vue` 文件后画布立即更新，并且保留当前状态 |
| 以"工作区"为入口 | 侧边栏的第一个操作是"新建工作区"，不再要求先连数据库 |
| 离线设计 | 不连任何数据库，也能创建和编辑设计模型 |
| 多数据源 | 每个工作区下可以有多个设计数据源（`design/`）和多个数据库数据源（`db/`） |
| 画布独立 | 画布（`canvas/`）只保存"放了哪些表、放在哪里"，用户可以把任意设计源、数据库源里的表加进来编排、编辑、对比 |

## 二、核心概念

```
工作区 (workspace)
├─ 设计数据源 (design source)   可编辑。tbls 格式的 schema.json + ext.json
├─ 数据库数据源 (db source)     只读。连接配置 + tbls 导出的快照
└─ 画布 (canvas)                引用上面的数据源，保存布局、分组、注释、对比关系
```

三条原则：

1. **数据源是唯一的数据来源，画布只保存引用和布局。** 在画布上修改一张设计表，改的是对应设计源的 `schema.json`；同一张表可以同时出现在多个画布里，改一处，所有画布都会更新。
2. **数据库数据源在画布上永远是只读的。** 数据库结构只能通过"同步"更新；要修改结构，由用户和 AI 生成 SQL，用户自己执行后再同步（和第一阶段的定位一致）。
3. **设计数据源始终保持标准 tbls 格式。** tbls 表达不了的信息放进 `ext.json`，保证 `tbls doc json://.../schema.json` 随时能直接渲染。

## 四、本阶段不做的事

- MCP Server（第三阶段）
- 从设计模型生成迁移 SQL（交给 AI 和用户，工具只提供差异上下文）
- 状态机、时序图等其他图类型
- 改名检测（改名仍然显示为"一边缺少、一边多出"）
- 多人协作、服务端存储

## 五、已确认的决定

| # | 问题 | 决定 |
| :-- | :-- | :-- |
| 1 | 开发时 Webview 怎么热更新？ | 开发模式下 Webview 的 HTML 指向 Vite 开发服务器（见 01 文档） |
| 2 | 允许有多个工作区吗？ | **允许**，自由添加 |
| 3 | 工作区放在哪里？ | **放在插件内部的存储目录**，不放进项目目录。可以用设置 `harness.storageDir` 改到别的目录（见 02 文档第二节） |
| 4 | 画布上能编辑数据库数据源里的表吗？ | **不能**，只读，只能调整布局 |
| 5 | 画布上按 Delete 会怎样？ | **只从画布移除**。要从设计模型中删除一张表，使用右键菜单"从设计模型中删除表…"，并在弹窗中二次确认 |
| 6 | 撤销和重做的范围 | 以画布为单位，覆盖布局操作和设计表的编辑操作（见 04 文档 7.3 节） |
| 7 | 第一阶段的数据要迁移吗？ | 不迁移，第一阶段只有测试数据 |
| 8 | 工作区、数据源、画布能改 ID 吗？ | 不能。"重命名"只改显示名称 |
