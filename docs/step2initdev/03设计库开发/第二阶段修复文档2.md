## 问题一：点击设计画布节点不打开画布

### 1.1 现状

当前树结构：

```
工作区 1
├─ 设计画布
│  └─ 设计画布 1        ← 点击：只展开/折叠子节点，不打开画布
│     ├─ 表结构（8）    ← 点击：打开画布（harness.design.open）
│     ├─ 设计图（2）
│     └─ 分区（2）
```

`workspaceTree.ts` 的 `design` 节点没有设置 `item.command`，只有 `Collapsed` 状态，所以点击只展开/折叠。而 `designTables` 节点绑定了 `item.command = harness.design.open`，点击才会打开画布。

用户期望：点击「设计画布 1」就应该打开画布，和点击「表结构」一样。

### 1.2 方案

给 `design` 节点加 `item.command`，指向 `harness.design.open`。VS Code 树的行为是：有 `command` 的可折叠节点，**单击展开 + 执行命令**，符合预期。

```typescript
// workspaceTree.ts  case 'design':
item.command = {
  command: 'harness.design.open',
  title: '打开画布',
  arguments: [node],
};
```

### 1.3 需要改动的文件

| 文件 | 改动 |
| :-- | :-- |
| `workspaceTree.ts` | `case 'design'` 的 `getTreeItem` 加 `item.command`，指向 `harness.design.open`，参数传 `node`（含 `workspace` 和 `id`） |

改动量：**1 行**。

## 问题二：数据库没有「显示全部表」按钮

### 2.1 现状

左侧「数据源」面板里：

- **设计表区**有「显示全部表（包括以后新增的）」checkbox → `designTables.set` op → 全部设计表隐式出现在画布上。
- **数据库区**每张表只有独立 checkbox，没有「全选/全不选」快捷操作。表多时逐个勾选很麻烦。

### 2.2 期望

数据库区也要有「全部显示」/「全部隐藏」的快捷操作。

### 2.3 方案分析

设计表的「显示全部表」走的是 `designTables` 模式切换（`'all'` / `'picked'`），这个机制专属于设计表（画布只有 `designTables` 字段，没有对应的 `dbTables` 字段）。数据库表没有类似的隐式模式——每张表要么在 `nodes` 里（显示），要么不在（不显示）。

因此数据库的「全部显示」不是模式切换，而是**批量操作**：一次性把所有表加入/移出 `nodes`。

#### UI 方案

在数据库源展开后的表列表上方加一个 checkbox（与设计表的 checkbox 位置对齐）：

```
🗄️ host:5432/app  [⟳] [✕]
  ☑ 显示全部表
  ☑ users
  ☑ orders
  ☐ logs
```

- 勾选：把该数据库所有（搜索过滤后的）表一次性 `nodes.put` 到画布
- 取消勾选：把该数据库所有表从画布 `nodes.remove`
- 半选状态（`indeterminate`）：部分表在画布上

#### 实现

在 `SourcePanel.vue` 的 DB section 里加一行 checkbox：

```vue
<label class="show-all">
  <input
    type="checkbox"
    :checked="allDbShown(g)"
    :indeterminate.prop="someDbShown(g)"
    @change="toggleAllDb(g, $event.target.checked)"
  />
  显示全部表
</label>
```

逻辑：

```typescript
function allDbShown(g) {
  return g.tables.length > 0 && g.tables.every(t => shown.has(t.id));
}
function someDbShown(g) {
  const count = g.tables.filter(t => shown.has(t.id)).length;
  return count > 0 && count < g.tables.length;
}
function toggleAllDb(g, on: boolean) {
  if (on) {
    const toAdd = g.tables.filter(t => !shown.has(t.id)).map(t => t.key);
    if (toAdd.length) emit('add-tables', g.sourceId, toAdd);
  } else {
    const toRemove = g.tables.filter(t => shown.has(t.id)).map(t => t.id);
    if (toRemove.length) emit('remove-nodes', toRemove);
  }
}
```

与设计表的区别：
- 设计表走 `designTables.set` 模式（以后新增的表也自动出现），checkbox 文案含「包括以后新增的」。
- 数据库走 `nodes.put` / `nodes.remove` 批量操作（快照不变时表不会变；同步后新增的表不会自动出现），checkbox 文案只写「显示全部表」。

### 2.4 需要改动的文件

| 文件 | 改动 |
| :-- | :-- |
| `SourcePanel.vue` | DB section 加全选 checkbox + `allDbShown` / `someDbShown` / `toggleAllDb` 逻辑 |

改动量：**小**（~20 行 template + script）。

## 问题三：左侧数据源和右侧面板需要可折叠

### 3.1 现状

当前画布编辑器的布局（`App.vue`）：

```
┌──────────────────────────────────────────────────┐
│ 工具栏                                            │
├──────────┬────────────────────────┬───────────────┤
│ 数据源    │                        │ 属性/差异/同步 │
│ (240px)  │        画布            │  (300px)      │
│ 固定宽度  │    (flex: 1)          │  固定宽度      │
│ 不可折叠  │                        │  不可折叠      │
└──────────┴────────────────────────┴───────────────┘
```

- 左侧 `.left` 固定 `width: 240px`，`flex-shrink: 0`。
- 右侧 `.right` 固定 `width: 300px`，`flex-shrink: 0`。
- 两者都没有折叠/展开的交互。

问题：屏幕较小时，画布区域被两侧挤压；用户不需要看数据源或属性面板时，无法收起。

### 3.2 期望

左侧和右侧面板都可以折叠/展开：
- 折叠后只显示一个窄条（图标 + 展开按钮），画布区域变大。
- 展开后恢复当前的宽度和内容。
- 记住折叠状态（至少在当前会话内）。

### 3.3 方案分析

#### 折叠交互

| 方案 | 说明 | 优缺点 |
| :-- | :-- | :-- |
| A. 折叠按钮 | 面板标题栏右侧加 `◀` / `▶` 按钮 | 操作明确，最常见 |
| B. 双击边框 | 双击分隔线折叠/展开 | 不够显眼，用户不易发现 |
| C. 拖拽宽度 | 支持拖拽改宽度，拖到极小时自动折叠 | 实现复杂，需要处理最小宽度、吸附等 |

**建议：方案 A**，简单明确。后续有需求再加拖拽。

#### 折叠后的样子

折叠后面板变成一个竖直的窄条（约 28–36px），上面放一个展开按钮和（可选的）竖排文字标签：

```
折叠前                              折叠后
┌──────────┬──────────┐           ┌──┬──────────┐
│ 数据源 ◀ │          │           │▶ │          │
│ ...      │  画布     │    →     │数 │  画布     │
│ ...      │          │           │据 │          │
│          │          │           │源 │          │
└──────────┴──────────┘           └──┴──────────┘
```

#### 实现

在 `App.vue` 加两个响应式变量 `leftCollapsed` 和 `rightCollapsed`：

```typescript
const leftCollapsed = ref(false);
const rightCollapsed = ref(false);
```

左侧面板 template：

```vue
<aside class="left" :class="{ collapsed: leftCollapsed }">
  <template v-if="!leftCollapsed">
    <div class="panel-toggle" @click="leftCollapsed = true" title="折叠数据源面板">◀</div>
    <SourcePanel ... />
  </template>
  <div v-else class="collapsed-bar" @click="leftCollapsed = false" title="展开数据源面板">
    <span class="collapsed-icon">▶</span>
    <span class="collapsed-label">数据源</span>
  </div>
</aside>
```

右侧面板类似，方向相反（`▶` / `◀`）。

CSS：

```css
.left.collapsed,
.right.collapsed {
  width: 32px;
  cursor: pointer;
}

.collapsed-bar {
  display: flex;
  flex-direction: column;
  align-items: center;
  gap: 4px;
  padding: 8px 0;
}

.collapsed-label {
  writing-mode: vertical-lr;
  font-size: 11px;
  color: var(--hn-muted);
}
```

#### 折叠按钮的位置

左侧面板的折叠按钮有两种放法：

- **放在 SourcePanel 的标题行**：在「数据源」标题右侧，和「+ 添加数据库」并排。需要 SourcePanel 接收一个 `@collapse` 事件或 slot。
- **放在 App.vue 的左侧容器顶部**：由 App.vue 自己渲染。SourcePanel 不需要改动。

**建议：放在 App.vue 容器顶部**，减少组件间耦合。折叠按钮作为面板标题行的一部分在 App.vue 渲染，SourcePanel 保持现在的功能不变。

右侧同理：tabs 行右侧加一个折叠按钮。

### 3.4 需要改动的文件

| 文件 | 改动 |
| :-- | :-- |
| `App.vue` | 加 `leftCollapsed` / `rightCollapsed` 状态；左右 `<aside>` 加折叠/展开逻辑和样式；折叠状态下渲染竖条 |

改动量：**中等**（~40 行 template + ~30 行 CSS）。不需要改 SourcePanel / Inspector / DiffPanel / SyncPanel 的代码。

## 问题四：分区应从 treeview 移到数据源面板

> **已被问题五取代。** 问题五把「分区（只是布局框）」升级为「分区画布（可嵌套的完整画布）」，分区重新回到 treeview，但以画布的身份出现。本节保留作为分析记录，不按本节实施。

### 4.1 现状

修复文档 1 实现后，分区（zone）作为树的子节点出现在侧边栏里：

```
设计画布 1
├─ 表结构（8）
├─ 设计图（2）
└─ 分区（2）        ← 在 treeview 中
   ├─ 订单模块（3 张表）
   └─ 用户模块（5 张表）
```

同时，`workspaceTree.ts` 需要读取 `lastCanvas` 的画布文件才能拿到分区数据，`commands/canvas.ts` 新增了 `zone.rename` / `zone.delete` 命令来修改画布文件。

### 4.2 问题

分区放在 treeview 里有几个不协调的地方：

1. **层级不匹配**：树是全局导航结构（工作区 → 设计画布 → …），分区是画布内部的局部布局概念。表结构和设计图是设计画布持久拥有的内容，分区只属于当前画布的某种摆放方式——放在同一级显得分区和表结构同等重要，实际不是。
2. **数据来源不自然**：表结构和设计图各有独立的存储目录（`schema.json`、`diagrams/`），树直接读取即可。分区数据藏在 `canvases/<canvasN>.json` 内部，树需要额外读取 `lastCanvas` → 解析画布文件 → 提取 zones 和 nodes 的 zone 归属，链路长且脆弱。
3. **交互割裂**：用户在画布里创建、拖动、调整分区，然后要去树里看结果。分区的所有编辑操作都发生在画布编辑器里，树只是个只读的镜像。
4. **多画布问题**：一个设计画布可以有多张画布，每张画布有自己的分区。树只能显示一张画布（lastCanvas）的分区，其他画布的分区看不到。

### 4.3 方案：分区移到数据源面板

分区应该和设计表、数据库一样，放在画布编辑器左侧的「数据源」面板里。这个面板展示的就是**当前画布上有什么**，分区是画布内容的一部分，归属自然。

调整后的数据源面板结构：

```
数据源                              [+ 添加数据库]
─────────────────────────────────────────
🔍 搜索表名或注释

✏️ 设计画布 1
  ☑ 显示全部表（包括以后新增的）
  ☑ users
  ☑ orders
  ☐ logs

📦 分区（2）
  ▾ 订单模块（3 张表）
    orders · order_items · payments
  ▸ 用户模块（5 张表）

🗄️ host:5432/app                  [⟳] [✕]
  ☐ 显示全部表
  ☑ users
  ☐ products
```

#### 分区区域的功能

| 项目 | 说明 |
| :-- | :-- |
| 标题 | 「分区（N）」，N 是当前画布的分区数 |
| 分区列表 | 每个分区显示名称 + 表数量，可展开显示归属的表名 |
| 点击分区名 | 画布定位到该分区（居中显示） |
| 点击分区内的表名 | 画布定位到该表 |
| 无分区时 | 显示提示「在工具栏点击 + 分区来创建」 |
| 右键菜单（可选） | 重命名、删除（复用画布里已有的分区操作） |

#### 数据来源

分区数据完全来自当前画布的 `canvas.zones` 和 `canvas.nodes[].zone`，`SourcePanel` 已经通过 `store` 拿到了 `canvas` 对象，不需要额外读取任何文件。这比 treeview 读 `lastCanvas` 自然得多。

### 4.4 树结构回退

分区从树里移除后，设计画布的子节点变回两个：

## 问题五：设计画布 = 可嵌套的分区画布（设计表 + 设计图 + 数据库表）

### 5.1 现状与问题

1. **画布上只能放表，不能放设计图。** 画布文件 `canvases/<canvasN>.json` 的 `nodes` 只有表节点（`source: 'design' | dbN`），设计图（状态图、流程图等）只能在单独的设计图编辑器里打开，画布上看不到。
2. **「多画布」和「分区」是两套概念。** 一个设计画布下可以有多张平级画布（工具栏下拉切换），每张画布里又有分区（`zones`，只是布局框）。两者都想表达「把一个大设计拆成几块」，但一个是平级、一个是框，用户难以理解。
3. **分区不能嵌套，也不能拥有自己的设计图。**

### 5.2 目标模型

**只有一个概念：设计画布。** 分区画布就是嵌套在另一个设计画布里的设计画布，结构完全相同，可以无限嵌套。

每个画布（根画布或分区画布）包含三类内容：

| 内容 | 含义 | 数据来源 |
| :-- | :-- | :-- |
| **设计表** | 用户设计的表，画布上显示为表节点 | 设计画布的 `schema.json` |
| **设计图** | ER 图、状态图、时序图、流程图、数据流图（Mermaid），画布上显示为 Mermaid 卡片 | `diagrams/<diagramN>.md` |
| **分区画布** | 嵌套的子画布，在父画布上显示为一个框，框里是子画布的内容 | 同一个设计画布内部 |

三类内容都可以上画布。设计表、设计图、分区画布之间的关系类似 Windows 的文件和文件夹：分区画布是文件夹，设计表和设计图是文件，可以**复制**、**剪切（迁移）**到别的分区画布。

另外，画布上还可以放**数据库表**（来自引用的数据库，只读，用于参考和对比）。

**树结构**：

```
工作区 1
├─ 设计画布
│  └─ 设计画布 1                ← 点击：打开根画布
│     ├─ 设计表（3）            ← 只列本层的表，不含分区里的
│     ├─ 设计图（1）
│     └─ 分区画布（2）
│        ├─ 订单                ← 点击：打开「订单」画布
│        │  ├─ 设计表（4）
│        │  ├─ 设计图（2）      ← 订单状态图、下单时序图
│        │  └─ 分区画布（1）
│        │     └─ 支付
│        │        ├─ 设计表（2）
│        │        ├─ 设计图（0）
│        │        └─ 分区画布（0）
│        └─ 用户
│           └─ …
└─ 数据库
   └─ host:5432/app
```

**画布编辑器**（点击任意一层画布打开）：

```
┌────────────────────────────────────────────────────────────────┐
│ 设计画布 1 › 订单                [+ 新建表] [+ 设计图] [+ 分区画布] … │  ← 面包屑，可点回上层
├────────────┬───────────────────────────────────┬───────────────┤
│ 数据源      │  ┌ orders ┐   ┌ order_items ┐    │ 属性/差异/同步  │
│ ▾ 设计表    │  └────────┘   └─────────────┘    │ （保持现状）    │
│   ☑ orders │                                   │               │
│   …        │  ┌─ 支付（分区画布）────────────┐  │               │
│ ▾ 设计图    │  │ ┌ payments ┐  ┌ refunds ┐   │  │               │
│   ☑ 订单状态│  │ └──────────┘  └─────────┘   │  │               │
│   ☑ 订单 ER │  └──────────────────────────────┘  │               │
│ ▾ 数据库    │  ┌ 订单状态图 ┐  ┌ 订单 ER 图 ┐   │               │
│   ☐ orders │  └────────────┘  └────────────┘   │               │
└────────────┴───────────────────────────────────┴───────────────┘
```

- **一个设计画布只有一个标签页**（对应根画布）。点击树里任何一层，都是打开这个标签页并切换到那一层；面包屑可以切回上层。
- 中间显示：本层的设计表 + 本层的设计图（含 ER 图）+ 放上来的数据库表 + **所有子分区画布（框内显示子画布的内容，递归）**。
- 左侧数据源：只显示**当前这一层画布**的数据，分三组：设计表 / 设计图 / 数据库。
- 右侧：保持现状（属性 / 差异 / 待同步）。

> 关于「工具栏」：指画布编辑器顶部那一行（画布名称、+ 新建表、+ 分区、+ 便签、自动布局、字段、对比…）。**这一行里现在没有画布下拉**。现在的「多画布」只存在于底层：一个设计画布下可以有多个 `canvases/*.json` 文件，以及 `canvas/switch`、`canvas/new` 消息和 `harness.canvas.*` 命令。新模型下去掉的是这些底层的东西；工具栏上只是把「+ 分区」换成「+ 分区画布」、「+ 设计图」，标题换成面包屑。

### 5.3 关键设计决定

#### 决定 1：表结构整个设计画布只有一份

所有层级共用根目录的一个 `schema.json`，分区画布只记录「哪些表放在我这层」，不单独存表结构。

| 方案 | 优点 | 缺点 |
| :-- | :-- | :-- |
| **A. 共用一份 schema.json（建议）** | 跨分区的外键关系自然成立；和数据库对比仍是一对一；tbls 格式不变 | 需要单独记录表属于哪个分区 |
| B. 每个分区一份 schema.json | 分区独立 | 跨分区外键没法表达；同名表冲突；对比数据库要先合并 |

#### 决定 2：每张设计表、每张设计图都属于一层画布

- 每张设计表、每张设计图都有且只有一个「所在画布」（根画布或某个分区画布），树里每层的「设计表」「设计图」只列本层的内容。
- 位置可以通过**复制 / 剪切 / 粘贴**或**拖拽**改变（见决定 3），树的目录跟着变化。
- 跨分区的外键关系照常画线，线会穿过分区框。
- 数据库表不属于任何一层，同一张数据库表可以放在不同分区里做参考。

#### 决定 3：复制和剪切（类似 Windows 文件操作）

| 操作 | 设计表 | 设计图 | 分区画布 |
| :-- | :-- | :-- | :-- |
| **剪切 + 粘贴（迁移）** | 表移到目标画布，原位置没有了；表名、字段、关系都不变 | 图移到目标画布，原位置没有了 | 整个分区（含里面所有内容）移到目标画布下 |
| **复制 + 粘贴** | 目标画布新增一张**独立的新表**，字段、索引、注释都复制；原表不变 | 目标画布新增一张新设计图，内容相同，名称加「副本」 | 整个分区深度复制（里面的表、图、子分区都复制一份） |

**复制表的命名**：所有层级共用一个 `schema.json`（决定 1），数据库里同一个 schema 下不能有两张同名表，所以复制出来的表**真实表名必须不同**。按目标画布有没有设置命名空间（决定 9）处理：

| 目标画布 | 复制 `orders` 后的真实表名 | 画布上显示 |
| :-- | :-- | :-- |
| 没有命名空间 | `orders_copy`（已有则 `orders_copy2` …），粘贴后直接进入改名状态 | `orders_copy` |
| 命名空间 = 数据库 schema `payment` | `payment.orders` | `orders`（标题旁灰色小标签 `payment.`） |
| 命名空间 = 表名前缀 `pay_` | `pay_orders` | `orders`（标题旁灰色小标签 `pay_`） |

所以「从父画布复制到子画布后显示同名」是可以的：给子画布设置命名空间即可。

**复制表时的关系**：
- 新表**引用别的表**的外键（例如 `orders_copy.user_id → users.id`）：一起复制。
- **别的表引用原表**的外键：不复制（仍然指向原表）。
- 一次复制多张表时，它们之间的外键改成指向新表（例如同时复制 `orders`、`order_items`，`order_items_copy.order_id → orders_copy.id`）。

**在哪里操作**：

| 位置 | 方式 |
| :-- | :-- |
| 树 | 右键「复制」「剪切」，在目标画布（或它的「设计表」「设计图」目录）上右键「粘贴」；拖拽 = 剪切，按住 Ctrl 拖拽 = 复制 |
| 画布 | 选中表 / 设计图 / 分区框，`Ctrl+C` / `Ctrl+X`，进入目标层或选中目标分区框后 `Ctrl+V`；把节点**拖进 / 拖出分区框** = 剪切到那个分区 |

**限制**：
- v1 只在同一个设计画布内部复制和剪切；跨设计画布以后再做（可以复用现有的 `copyTableOps`）。
- 分区画布不能剪切到它自己或它的子分区里面。
- 这里的剪贴板是插件内部的，和系统剪贴板、「复制给 AI」无关。

#### 决定 4：删除分区画布 = 连同里面的内容一起删除

删除前弹窗列出影响范围，确认后才删除：

```
确定删除分区画布「订单」吗？
将一起删除：
  · 2 个子分区画布（支付、退款）
  · 9 张设计表（orders、order_items、payments …）
  · 3 张设计图（订单状态图、下单时序图、订单 ER 图）
  · 其他分区的 2 个外键关系会一起删除（users → orders …）
数据库不受影响。
                                 [删除]  [取消]
```

- 设计表从 `schema.json` 删除，设计图文件删除，放在里面的数据库表节点、便签一起移除。
- 在画布编辑器里删除时可以 `Ctrl+Z` 撤销（设计图内容在撤销记录里保留一份，撤销时写回文件）。
- 打开着的相关设计图编辑器标签页会关闭。

#### 决定 5：在哪层创建，就属于哪层，默认显示

不再有「未放置的表」和「显示全部表（包括以后新增的）」的概念：

| 新建方式 | 属于哪层 |
| :-- | :-- |
| 画布上「+ 新建表」/ 双击空白处 / 「+ 设计图」 | 当前这一层；如果是在某个分区框里双击，属于那个分区 |
| 树里某层「设计表」「设计图」目录上右键新建 | 那一层 |
| ER 图同步生成的新表 | ER 图所在的那一层 |
| 把数据库表复制到设计（`table/copyToDesign`） | 那张数据库表节点所在的那一层 |
| 在插件外部直接改了 `schema.json` / `diagrams/`（手动或 AI），布局里没有记录的表或图 | 根画布，放在现有内容右侧 |

- 新建的表和图**默认显示**在画布上。
- 左侧数据源里可以取消勾选来**隐藏**（只是不显示，仍然属于这一层，树里仍然能看到）。
- 通过拖拽或剪切改变所在层（决定 3）。
- 画布上按 `Delete` 仍然是**隐藏**，从设计里删除表要走右键「删除表」+ 二次确认（和现在一样）。

#### 决定 6：一个设计画布一个布局文件、一个标签页

| 方案 | 优点 | 缺点 |
| :-- | :-- | :-- |
| **A. 一个 `layout.json`，里面记录所有分区画布（建议）** | 父画布要同时显示子画布内容，一个文件读写最简单；撤销/保存只有一个文档；移动分区只改一个字段 | 文件会随设计变大（表节点只存坐标，规模可接受） |
| B. 每个分区画布一个文件 | 和「每层都是画布」的概念一一对应 | 父画布显示子画布、在父画布里拖动子画布的表，都要跨文件编辑；撤销栈分散在多个文档；很容易出现不一致 |

采用 A：**一个设计画布只对应一个标签页（根画布）**。点击树里不同层级的画布，打开的都是这个标签页，只是切换「当前显示哪一层」（面包屑可以切回上层）。撤销、保存、脏状态都只有一份。（已确认）

#### 决定 7：所有类型的设计图都能上画布

- 设计图文件仍在 `diagrams/<diagramN>.md`，文件格式不变。属于哪一层记录在 `layout.json` 里（不写进设计图文件，这样 AI 改设计图内容时不会误改位置）。
- 画布上显示设计图：新节点类型「设计图卡片」，里面是 Mermaid 预览（复用现有的 `MermaidPreview.vue`），可以调整卡片大小，双击打开设计图编辑器。
- 工具栏「+ 设计图」：选类型 → 空白 / 粘贴 Mermaid → 创建在当前这层，并放到画布上。
- **ER 图也上画布**，显示 Mermaid 渲染的 ER 图。它和画布上的设计表节点是两种视图：
  - 设计表节点：用来编辑（改字段、连关系）。
  - ER 图卡片：Mermaid 格式，用来写文档和展示（以后做文档导出、可视化时直接用）。
  - ER 图和表结构不一致时，卡片右上角显示「待同步 N」，点击打开右侧「待同步」页签（现有功能）。

#### 决定 8：取代现有的「多画布」和「分区（zones）」

- 一个设计画布只保留一个布局文件（`layout.json`），去掉 `canvases/*.json` 多文件、`canvas/switch` / `canvas/new` / `canvas/copy` 消息和 `harness.canvas.*` 命令。需要另一块区域就新建分区画布。
- `zones`（纯布局框）去掉：分区画布的框就是原来的分区。
- 旧数据都是测试数据，不做迁移。

#### 决定 9：分区画布的命名空间（同名显示）

**问题**：从父画布复制 `orders` 到子画布，希望子画布里也叫 `orders`。但所有表在同一个 `schema.json` 里，真实表名不能重复。

**思路**：真实表名必须唯一，**显示名**可以相同。每个分区画布可以设置一个可选的**命名空间**，画布上显示时去掉命名空间，只显示短名。

| 命名空间类型 | 例子 | 真实表名 | 显示名 | 说明 |
| :-- | :-- | :-- | :-- | :-- |
| 不设置（默认） | — | `orders_copy` | `orders_copy` | 复制时加 `_copy` 后缀 |
| **数据库 schema** | `payment` | `payment.orders` | `orders` | 真实数据库里就是 `payment` schema 下的 `orders` 表，**短名真的相同**。tbls 本来就用 `schema.表名` 表示非默认 schema 的表，和数据库对比能直接对上。适用于 PostgreSQL、SQL Server、Redshift 等支持多 schema 的库 |
| **表名前缀** | `pay_` | `pay_orders` | `orders` | 真实表名带前缀，显示时去掉。MySQL、SQLite 等不方便用多 schema 的库用这个 |

**规则**：

1. 命名空间在分区画布上设置（新建分区画布时可选填，之后可以在「编辑…」里改）。子分区不设置时**继承**父分区的命名空间。
2. 在有命名空间的画布里**新建表**：输入 `refunds`，真实表名自动变成 `payment.refunds` / `pay_refunds`。
3. **复制**到有命名空间的画布：短名不变，真实表名换成目标画布的命名空间（见决定 3 的表）。如果目标画布里已经有同样的短名，才加 `_copy`。
4. **剪切**（迁移）默认**不改真实表名**（迁移不应该悄悄改表名）。如果表名和目标画布的命名空间不一致，粘贴时询问：「同时改名为 `payment.orders` 吗？」[改名] [保持原名]。保持原名时画布上显示完整名。
5. 显示名只在画布、树、左侧数据源里用。属性面板、差异、SQL、Mermaid、「复制给 AI」一律用**真实表名**，避免混淆。画布上带命名空间的表，标题旁用灰色小标签标出命名空间，鼠标悬停显示真实表名。
6. 同一个画布里，显示名也不能重复（例如 `payment.orders` 和一个没有命名空间的 `orders` 剪切到同一层，后者显示完整名）。

**复制整个分区画布（深度复制）**：

- 被复制的分区有命名空间时：副本的命名空间默认是 `原命名空间_copy`（例如 `payment_copy` / `pay_copy_`），可以在粘贴时改；里面所有表的**短名保持不变**，只换命名空间。
- 被复制的分区没有命名空间时：里面每张表按 `_copy` 规则改名。
- 分区画布自己的名称加「副本」（例如「支付 副本」）；里面的设计图名称也加「副本」。
- 副本里的表之间的外键指向副本里的表；指向副本外面的外键保持不变（和决定 3 的规则一致）。

### 5.4 存储结构

```
design/<designN>/
├─ design.yml              name, description, sources:[dbN…], seq:{partition, diagram}
├─ schema.json             不变（全部设计表）
├─ ext.json                不变
├─ comparisons.json        不变
├─ layout.json             ★ 新：替代 canvases/*.json，记录所有层级、每张表和图在哪层
└─ diagrams/<diagramN>.md  文件格式不变
```

`layout.json`（version 3）：

```jsonc
{
  "version": 3,
  "partitions": [
    { "id": "part1", "name": "订单", "x": 600, "y": 0, "collapsed": false },
    { "id": "part2", "name": "支付", "parent": "part1", "x": 40, "y": 320,
      "namespace": { "kind": "schema", "value": "payment" } }   // 可选，决定 9；kind: schema | prefix
  ],
  // 设计表：以表名为键，天然保证一张表只在一个位置
  // 坐标相对于所在画布（根画布 = 绝对坐标；分区画布 = 相对分区框左上角）
  "tables": {
    "users":  { "x": 0, "y": 0 },
    "orders": { "partition": "part1", "x": 20, "y": 40 },
    "logs":   { "x": 0, "y": 400, "hidden": true }
  },
  // 设计图：以设计图 ID 为键
  "diagrams": {
    "diagram1": { "x": 400, "y": 0, "width": 360, "height": 240 },
    "diagram2": { "partition": "part1", "x": 20, "y": 600, "width": 360, "height": 240 }
  },
  // 数据库表：不属于任何层，只是放在某层上做参考，同一张表可以放多处
  "dbNodes": [
    { "db": "db1", "table": "orders", "partition": "part1", "x": 400, "y": 40 }
  ],
  "notes": [ { "id": "n1", "partition": "part1", "text": "…", "x": 0, "y": 0, "width": 200 } ],
  "comparison": { "db": "db1", "mode": "overlay" },
  "settings": { "columnDisplay": "all" },
  "viewports": { "root": { "x": 0, "y": 0, "zoom": 1 }, "part1": { "x": 0, "y": 0, "zoom": 1 } }
}
```

- 分区画布的 ID（`partN`）由 `design.yml` 的 `seq.partition` 分配，只增不复用，和现有 ID 规则一致。
- 分区框的**宽高不存**，按框内内容自动计算（内容包围盒 + 内边距），避免框和内容不一致。
- 设计表 / 设计图属于哪层 = `tables[名].partition` / `diagrams[ID].partition`，不写表示根画布。剪切 = 改这个字段；复制 = 新建表或图，再加一条记录。
- `hidden: true` = 属于这一层但不在画布上显示（左侧数据源取消勾选）。
- `schema.json` 里有、`layout.json` 里没有记录的表（例如 AI 直接改了 `schema.json`）：当作根画布的表显示，下次保存时写入记录。设计图同理。
- 去掉 `designTables: 'all' | 'picked'`（决定 5）。

### 5.5 画布显示：嵌套和窗口大小

用 Vue Flow 的父子节点（`parentNode`）实现嵌套：分区框是一个父节点，框里的表、设计图、子分区框都是它的子节点，坐标相对父节点，拖动分区框时子节点一起移动（不需要现在的手动算位移）。

嵌套多了画布会很大，处理方法：

| 手段 | 说明 |
| :-- | :-- |
| **框自动撑大** | 分区框大小跟随内容；拖动框里的表到边缘时框自动变大 |
| **折叠分区框** | 每个框标题栏有折叠按钮，折叠后只显示「支付 · 2 张表 · 1 张图」小卡片；状态存在 `partitions[].collapsed` |
| **默认展开深度** | 打开某层画布时，默认展开 2 层子分区，更深的自动折叠（可以手动展开） |
| **进入分区** | 双击分区框标题 = 切换到该分区画布（面包屑出现一级），画布只显示这一层及其子分区 |
| **缩小时简化显示** | 缩放小于一定比例时，表节点只显示表名，设计图卡片只显示标题，减少渲染量 |
| **适应窗口** | 切换层级后自动 `fitView` 到这一层的内容 |
| **自动布局** | 复用现在 `layoutWithZones` 的 ELK 复合节点布局，把分区框当复合节点，支持多层 |

| `workspace/refactor.ts` | 表改名同步 `layout.json`；删除分区画布时汇总影响范围（子分区、表、图、跨分区外键）用于弹窗 |
| Webview `store.ts` / `viewModel.ts` | 状态加 `scope`；`buildView` 按层级生成嵌套节点（父子关系、折叠、深度）；设计图卡片 |

| `canvas/layout.ts` | `layoutWithZones` 扩展为多层复合节点布局 |

改动量：**大**，相当于第二阶段 A 步骤的规模。建议分步：

1. **P1 数据层**：`layout.json` 类型、op、存储、复制剪切纯函数、测试（不动界面）
2. **P2 树**：递归的设计画布 / 分区画布节点，点击打开并切换层级（含问题一）；右键复制 / 剪切 / 粘贴、拖拽
3. **P3 编辑器**：层级切换、面包屑、嵌套分区框渲染、拖入拖出分区、`Ctrl+C / X / V`、删除分区画布
4. **P4 设计图上画布**：设计图卡片（含 ER 图）、`+ 设计图`
5. **P5 数据源面板**：三组数据源、全部显示（含问题二）、左右面板折叠（问题三）
6. **P6 清理**：删除 `canvases/`、`zones`、`designTables`、`canvas.*` / `zone.*` 命令和相关消息，更新 README

### 5.9 已确认

| # | 问题 | 结论 |
| :-- | :-- | :-- |
| 1 | 一张表能否出现在多个分区 | 不做「引用」。表和图属于一层，可以像 Windows 文件一样**复制**（新增一份）或**剪切**（迁移），树的目录同步变化（决定 2、3） |
| 2 | ER 图是否上画布 | ER 图、其他设计图、设计表**都能上画布**；ER 图用 Mermaid 显示，以后用于文档化和可视化（决定 7） |
| 3 | 标签页 | 每个分区画布不单独开标签页，**一个标签页对应根画布**，切换层级（决定 6） |
| 4 | 工具栏 / 多画布下拉 | 工具栏指画布编辑器顶部那一行，其中没有画布下拉；去掉的是底层的多画布文件和命令。左侧数据源只显示当前这层的数据（决定 8、5.6） |
| 5 | 删除分区画布 | 里面的内容**全部删除**，删除前弹窗列出影响范围（决定 4） |
| 6 | 未放置的表 | 不再有这个概念。**在哪层创建就属于哪层，默认显示**；通过拖拽改变所在层（决定 5） |

### 5.10 第二轮确认

| # | 问题 | 结论 |
| :-- | :-- | :-- |
| 1 | 复制表必须换名 | 接受。另外希望子画布里能显示同名 → 分区画布加**命名空间**（数据库 schema 或表名前缀），真实表名唯一，显示短名（决定 9） |
| 2 | 复制分区画布 | v1 就支持**深度复制**，命名按决定 9：有命名空间的换命名空间、短名不变；没有的加 `_copy` |
| 3 | 删除分区画布的撤销 | 接受：编辑器里可以 `Ctrl+Z`，树里删除且编辑器没打开时只有弹窗确认 |

### 5.11 第三轮确认

| # | 问题 | 结论 |
| :-- | :-- | :-- |
| 1 | 同名显示的做法 | 采用**命名空间**（方案 C）：画布上看到什么，数据库里就是什么。不做「只改显示名」的别名方案 |
| 2 | 命名空间类型 | v1 两种都做：数据库 schema（PostgreSQL、SQL Server、Redshift 默认）和表名前缀（MySQL、MariaDB、SQLite、ClickHouse 默认）；新建分区画布时可以不设置 |
| 3 | 继承 | 子分区不设置时继承父分区的命名空间 |

**状态**：全部确认，已按 P1 → P6 实施完成（typecheck、132 个单元测试、build 通过；尚未在真实 Cursor 环境完整走查）。

### 5.12 实现与方案的偏差

实现时和上面方案不一致的地方，以这里为准：

| # | 方案 | 实际实现 | 原因 |
| :-- | :-- | :-- | :-- |
| 1 | `layout.json` 用 `tables` 对象 + `dbNodes` 数组，文件改名 `shared/layout.ts` | 仍叫 `shared/canvas.ts` / `CanvasFile`，`nodes` 是一个数组（设计表 `source:'design'`、数据库表 `source:dbN` 放在一起），每条带 `partition` / `hidden` | 复用现有 `nodes.*` op 和画布代码，改动小；按 `source/table` 去重同样保证一张表只在一处 |
| 2 | 数据库表同一张可以放多处 | 一个设计画布里一张数据库表只在一层 | 节点 ID 是 `source/table`，放多处要引入实例 ID，v1 不需要 |
| 3 | 分区 ID 由 `design.yml` 的 `seq.partition` 分配 | 存在 `layout.json` 的 `seq` | 分区只存在于布局里，撤销时编号和布局一起回退也不会复用（取 max） |
| 4 | op 名：`table.place/hide`、`diagram.place/hide`、`dbNode.put/remove` | `nodes.put/remove/display`、`diagrams.put/remove`、`hidden.set`（表和图通用）、`move`、`partition.put/remove`、`note.put/remove` | 同上 |
| 5 | 树上拖拽 = 剪切，按 Ctrl = 复制 | 树上拖拽只做移动；复制用 Ctrl+C / V 或右键 | VS Code 树拖拽拿不到 Ctrl 状态 |
| 6 | 命名空间默认：PostgreSQL、SQL Server、Redshift 用 schema | 另外 Oracle 也默认 schema；前缀自动补 `_` | Oracle 同样有真实 schema |
| 7 | 复制时数据库表跟着复制 | 复制 / 剪切时跳过数据库表（数据库表只能在画布上拖动换层） | 数据库表不属于设计，复制没有意义 |
| 8 | 复制 ER 图 | 只把 frontmatter `refs` 改成副本表名，Mermaid 代码里的表名不改写 | 改写代码容易破坏用户手写内容；打开副本后按"待同步"处理 |
| 9 | `viewports` | 按层存（`root` / `partN`），切换层级时恢复该层视口，没有记录时 fitView | 和方案一致，补充说明 |
| 10 | 设置命名空间只影响新建表 | 设置时可以选择是否把本层已有的表一起改名（真实表名变化，走撤销栈） | 否则已有表显示成长名，和命名空间的意义不一致 |
| 11 | 分区框大小 | 宽高不存，按内容包围盒 + 内边距自动计算，有最小尺寸；折叠后固定小卡片 | 和方案一致，补充说明 |
| 12 | ER 图同步出新表 | ER 图同步新增的表放到这张图所在的层 | 方案未说明 |
| 13 | 默认展开 2 层子分区 | 未实现，只按每个框的 `collapsed` 显示 | 先看实际使用中嵌套多深再定 |
| 14 | 左侧列表项支持右键复制 / 剪切、拖到画布 | 未实现，在画布或树上操作 | v1 范围控制 |
| 15 | 从画布新建设计图 | 只在画布上放卡片，不自动打开设计图编辑器（从树新建仍会打开）；双击卡片打开 | 避免打断画布上的操作 |
| 16 | 键盘 | `Esc` 返回上一层；`Delete` = 隐藏（右键「删除表」才真删） | 补充说明 |
| 17 | 拖放目标 | 只有展开的分区框可以作为拖放目标，折叠的框不行（可以先进入再放） | 折叠框没有内部坐标 |
| 18 | 删除 `canvases/` | 旧的 `canvases/*.json` 不迁移也不删除，只是不再读取；设计表自动显示在根画布 | 开发阶段数据，避免误删用户文件 |
| 19 | 缩小时简化显示 | 未实现 | 待性能需要时再做 |
