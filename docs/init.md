**一句话：一个以“抽象模型层”为唯一真相源的业务可视化与文档化工具，让人类和 Agent 围绕同一份模型协同工作。**

更具体地说：

### 核心目标

- **设计阶段**：人类和 Agent 协同设计业务模型（用例、类、状态、时序、ER），通过可视化确认语义；
- **开发阶段**：从数据库读取实际表结构，反向同步到模型层，让模型始终反映工程真实状态；
- **人机共享**：同一份模型，派生出人类可读的图（PlantUML）和 Agent 可读的结构化数据（JSON）；
- **避免失控**：防止人类在开发过程中逐渐失去对工程的掌控，也防止 Agent 自由发散地改代码。

### 关键设计原则

| 原则                      | 含义                                       |
| :------------------------ | :----------------------------------------- |
| 模型是唯一真相源          | 图和数据都是模型的派生物，不是源           |
| 图是只读渲染目标          | 人类不直接编辑 PlantUML，编辑的是模型      |
| 单向派生                  | 模型 → PlantUML / JSON，不做反向转换       |
| 人类界面与 Agent 界面分离 | 看板给人用，MCP 给 Agent 用，共享同一模型  |
| 双向同步                  | 设计阶段正向建模，开发阶段从数据库反向同步 |

### 最终形态

text

```
模型设计看板（人类）
        ↕
   抽象模型层（唯一真相源）
        ↕
   MCP Server（Agent）
        ↓
Cursor / Codex / DeepSeek Harness
```

# 二、怎么做

## 1. 先定义模型层（地基）

这是整个工具的核心，必须先想清楚。

- 定义一套**统一元模型**：实体、属性、关系、状态、转移、消息、用例；
- 用 JSON/YAML 作为序列化格式；
- 模型要能同时表达设计阶段的类图/状态图/时序图，和开发阶段的表结构/ER 图；
- 参考 pgModeler 的做法：模型存 XML/JSON，从模型生成 SQL、图、diff。

**产出**：一份模型 Schema 定义 + 持久化格式。

## 2. 做看板 UI（人类界面）

- 技术选型：**VS Code Webview 插件**（React + React Flow），比 Cursor 插件更合适；
- 布局参考：左侧模型树、中间画布、右侧属性面板、底部 Agent 对话；
- 交互原则：用户感觉在画图，底层改的是模型；
- 编辑粒度：先做表单式 + Agent 生成候选，图形拖拽后置。

**产出**：一个能编辑模型、实时派生 PlantUML 渲染的 VS Code 插件。

## 3. 做 MCP Server（Agent 界面）

- 独立进程/服务，不绑死在 IDE 上；
- 暴露模型查询和编辑接口：`get_entity`、`get_relations`、`create_entity`、`update_state_transition` 等；
- Agent 拿到的是结构化 JSON，不是 PlantUML 文本；
- 参考 NeoSQL 的 MCP 集成方式：通过 project-ID 安全访问，不直接暴露数据库连接。

**产出**：一个 MCP Server，让 Cursor/Codex/DeepSeek Harness 能操作模型。

## 4. 做数据库接入（开发阶段）

- 用类似 dbclient 的能力连接数据库、读取 Schema；
- 把实际表结构**反向同步**到模型层；
- dbclient 的角色是**数据源接入层**，不是核心；
- 参考 ChartDB/drawDB 的“从数据库导入 Schema 生成图表”能力。

**产出**：一个能从数据库读取结构并更新模型的模块。

## 5. 做 Agent 协同闭环

- 设计阶段：Agent 通过 MCP 生成候选模型，人类在看板确认；
- 开发阶段：Agent 通过 MCP 查询模型，生成 SQL 实际写入数据库；
- 验证闭环：模型变更 → 派生 SQL → 执行 → 数据库反向同步 → 模型更新。

**产出**：人机协同的完整工作流。

------

## 建议的实施顺序

1. **先定义模型 Schema**（最容易被跳过，但最重要）；
2. **做最小看板**：能编辑模型 + 派生 PlantUML；
3. **做 MCP Server**：让 Agent 能读写模型；
4. **接数据库**：开发阶段反向同步；
5. **扩展生态**：从 VS Code 扩展到 Cursor、Codex、DeepSeek Harness。
