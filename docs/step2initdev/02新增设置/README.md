# 第二阶段补充：减少新建时的输入，数据库连接页面（最终版）

## 一、要解决的问题

第二阶段的第一版试用下来，新建任何东西都要在 Cursor 顶部的输入框里连续回答好几个问题：

| 新建什么 | 现在要回答的问题 |
| :-- | :-- |
| 工作区 | 名称 → ID → "接下来要做什么" |
| 设计模型 | 名称 → ID → 初始内容 → 目标数据库类型 → 在哪个画布打开（新画布还要再输名称和 ID） |
| 数据库 | 名称 → ID → 连接方式 → 手写一整条连接串 → 是否立即同步 |
| 画布 | 名称 → ID → 选数据源 → 全部表还是挑选 → 是否开启对比 |

问题有三个：

1. **ID 对用户没有意义。** 它只是目录名，用户却必须理解它的格式规则。
2. **名称可以有默认值。** 大多数时候用户并不在意叫什么，事后再改就行。
3. **手写连接串容易出错。** 用户要记住每种数据库的连接串格式，密码里有 `#`、`@` 这类字符时还要自己做 URL 编码。写错了也只能在同步时才发现，而且此时数据源已经建好了。

## 二、改完之后的样子

| 新建什么 | 用户的操作 | 结果 |
| :-- | :-- | :-- |
| 工作区 | 点 `+` | 立即出现"工作区 1"（目录 `workspace1`），里面自带一个空画布"画布 1" |
| 设计模型 | 点工作区里设计分组的 `+` | 立即在这个工作区的"设计"分组下出现"设计模型 1"（目录 `design/design1/`）并选中。**不自动加入画布** |
| 画布 | 点画布分组的 `+` | 立即出现"画布 2"并打开 |
| 数据库 | 点数据库分组的 `+` | 在编辑区打开**连接页面**：先选数据库类型，再填主机、端口、账号、密码 → 测试连接 → 连接。连接成功才创建数据源并读取表结构。**不自动加入画布** |

- 名称全部有默认值，改名用右键"重命名"或者按 F2；画布名称还可以直接在画布工具栏上点击修改。
- ID 由插件内部按顺序生成，界面上不出现。
- 把设计模型、数据库放进画布，统一在画布左侧数据源面板的"+ 添加"里操作，或者在树节点右键"添加到画布…"。

## 四、已确认的决定

| # | 问题 | 决定 |
| :-- | :-- | :-- |
| 1 | 内部 ID 的格式 | `workspace<N>`、`design<N>`、`db<N>`、`canvas<N>`，序号**只增不减**，删除后的 ID 不再复用（原因见 01 文档 2.2 节） |
| 2 | 新建工作区时要不要自动建一个空画布？ | 要，叫"画布 1" |
| 3 | 新建设计模型之后做什么？ | 只在工作区的"设计"分组下显示并选中，文件放在 `design/<ID>/` 目录下。不自动加入画布，也不自动打开画布 |
| 4 | 新建数据库之后要不要自动加入画布？ | 不自动加入 |
| 5 | 主机地址、用户名存在哪里？ | 和密码一起存进系统凭据，不写入任何文件。数据库的默认名称不带主机地址，例如"PostgreSQL · orders" |
| 6 | 连接数据库时怎么选数据库类型？ | 连接页面的第一个字段就是"数据库类型"，切换类型后表单字段、默认端口、加密选项随之变化 |
| 7 | "测试连接"和"连接"的关系 | "测试连接"是可选的。"连接"按钮本身会先测试，成功才创建数据源；测试时读到的结构直接复用，不再读第二遍 |
| 8 | 设计模型的目标数据库类型怎么选？ | 新建时不询问，自动推断（见 01 文档 3.2 节），之后可以在右键菜单"目标数据库类型…"里修改 |
| 9 | 要不要读取表里的数据？ | 这次不做。tbls 只能读取结构（见 03 文档） |
