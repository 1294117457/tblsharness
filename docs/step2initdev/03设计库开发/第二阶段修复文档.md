## 问题一：树结构调整 — 去掉「画布」中间层，加上「分区」

### 1.1 现状

当前 treeview 结构（A2 实现）：

```
工作区 1
├─ 设计画布
│  └─ 设计画布 1
│     ├─ 表结构（12 张表）   → 表 → 字段
│     ├─ 画布（2）           → 画布 1、画布 2
│     └─ 设计图（3）         → ER 图 1、状态图 1 …
└─ 数据库
   └─ host:5432/app          → 表 → 字段
```

问题：
- 「画布」作为中间层增加了导航深度，点击设计画布后还要再进一层才能操作。
- 「分区」只在画布编辑器内部可见，树上看不到。

### 1.2 期望

去掉「画布」目录，用「分区」替换它。每个设计画布直接展示三个子目录：

```
工作区 1
├─ 设计画布
│  └─ 设计画布 1
│     ├─ 表结构（8 张表）     → 表 → 字段
│     ├─ 设计图（2）          → ER 图 1、状态图 1
│     └─ 分区（2）            → 分区 1（3 张表）、分区 2（5 张表）
│  └─ 设计画布 2
│     ├─ 表结构（4 张表）
│     ├─ 设计图（1）
│     └─ 分区（1）
└─ 数据库
   └─ host:5432/app            → 表 → 字段
```

### 1.3 分析

#### 画布去哪了？

画布不是被删除，而是**不再暴露在树结构里**。底层存储不变：一个设计画布仍然可以包含多张画布（`canvases/*.json`），但用户在树上只看到设计画布这一级，点击设计画布节点直接打开最近使用的画布。多画布切换保留在画布编辑器的**工具栏下拉**中（已实现）。

| 操作 | 现在（树里有画布目录） | 调整后（树里无画布目录） |
| :-- | :-- | :-- |
| 打开画布 | 展开画布目录 → 点画布 1 | 直接点击「设计画布 1」→ 打开最近画布 |
| 切换画布 | 树里点另一张画布 | 画布编辑器工具栏下拉选择 |
| 新建画布 | 树里画布目录右键 → 新建 | 工具栏下拉 → 新建画布 |
| 删除画布 | 树里右键画布 → 删除 | 工具栏下拉 → 右键/删除按钮 |

#### 分区在树里显示什么？

分区来自**当前打开的画布**的 `zones` 数组。每个分区节点展示：
- 名称（如「订单」）
- 描述：包含的表数量（如「3 张表」）
- 展开后列出所属的表名

| 项目 | 说明 |
| :-- | :-- |
| 数据来源 | 当前画布（`lastCanvas`）的 `zones` + `nodes[].zone` |
| 分区节点操作 | 右键：重命名、删除分区 |
| 分区内的表 | 只读列表，点击可以在画布中定位该表 |
| 无分区时 | 显示占位文字「还没有分区，在画布中添加」 |

#### 表结构的展示范围

两种可选方案：

**方案 A — 显示设计的全部表（与现在一致）**
- 表结构节点下列出 `schema.json` 的所有表，不管画布上有没有放。
- 优点：概念简单，「表结构 = 这个设计的所有表」。
- 缺点：有些表没有放到画布上但仍然出现在树里。

**方案 B — 只显示当前画布上的表**
- 按 `nodes` 过滤（`designTables: all` 时显示全部）。
- 优点：和画布保持一致。
- 缺点：切换画布后树里的表会变；不在任何画布上的表就看不到了。

**建议：方案 A**，和现在一致，改动最小。

### 1.4 命名问题：「设计图」和「视图」

用户反馈两个名字容易混淆。分析：

| 候选名 | 指代 | 优缺点 |
| :-- | :-- | :-- |
| **视图** | 分区 / zone | 与数据库 VIEW 概念冲突（代码里 `isView` 判断表类型）；与「设计图」的「图」字重复 |
| **分区** | 分区 / zone | 含义清晰，不与任何已有概念冲突；代码里已统一使用 `zone` |
| **设计图** | Mermaid 图 | 含义明确（ER 图、状态图等），用户已熟悉 |

**建议**：
- **保留「分区」**，不引入「视图」。「分区」含义清晰，代码里已统一使用 `zone`。
- **保留「设计图」**不变。
- 树上三个子目录叫：**表结构**、**设计图**、**分区**。

### 1.5 需要改动的文件

| 文件 | 改动 |
| :-- | :-- |
| `workspaceTree.ts` | `TreeNode` 去掉 `canvasGroup` / `canvas` 两种 kind；新增 `zoneGroup` / `zone` 两种 kind；`getChildren(design)` 返回 `[designTables, diagramGroup, zoneGroup]`（去掉 canvasGroup）；新增 `getChildren(zoneGroup)` 读画布 zones；新增 zone 节点的 `getTreeItem` |
| `workspaceTree.ts` | zone 节点需要读当前画布文件 → 找到 `lastCanvas` → 读该画布的 zones 和 nodes |
| `package.json` | 去掉 `canvasGroup` / `canvas` 的右键菜单项；新增 `zoneGroup` / `zone` 的菜单（重命名、删除） |
| `commands/canvas.ts` | 新建/删除/重命名画布的操作从树迁移到画布编辑器工具栏下拉（现有的 `canvas/new` 等消息已支持） |

改动规模：**小**。只是树节点的增删，底层存储和画布编辑器不变。

## 问题二：「显示全部表」再次点击应取消

### 2.1 现状

左侧「数据源」面板中，「显示全部表（包括以后新增的）」checkbox 的行为：

1. **首次勾选**：`designTables` 设为 `'all'`，所有设计表立刻显示在画布上。
2. **再次取消勾选**：调用 `materialize()`，把当前隐式存在的节点全部写入 `nodes`，然后把 `designTables` 设为 `'picked'`。

结果：**取消勾选后，画布上的表数量不变**（只是从「自动全部」变成了「逐个勾选了全部」）。用户感知上没有变化，以为「取消没生效」。

### 2.2 期望行为

再次点击取消勾选时，**之前因 all 模式自动出现的表应该消失**，只保留用户手动放置过的表。

### 2.3 方案

取消勾选时只发 `designTables.set` op，**不调用 `materialize()`**。

```typescript
function setDesignShowAll(all: boolean) {
  if (all) {
    editCanvas('显示全部表', [{ op: 'designTables.set', mode: 'all' }]);
  } else {
    // 只切模式，不 materialize → 自动出现的表消失，用户手动放的表保留
    editCanvas('取消显示全部表', [{ op: 'designTables.set', mode: 'picked' }]);
  }
}
```

效果：
- 在 `'all'` 模式下用户移动过位置的表 → 已写入 `nodes` → **保留**
- 用户没碰过的表 → 不在 `nodes` 里 → **消失**

行为符合直觉：「显示全部」是临时预览开关，取消后回到之前手动挑选的状态。

### 2.4 需要改动的文件

| 文件 | 改动 |
| :-- | :-- |
| `SourcePanel.vue` | `setDesignShowAll(false)` 不再 `emit('pick-mode')`，改为直接发 `designTables.set` op |

改动量：**约 2 行代码**。
