# 04 tbls 配置

> tbls 是用 Go 写的命令行工具（[k1LoW/tbls](https://github.com/k1LoW/tbls)），插件通过 `tbls out -t json` 读取数据库结构。当前只用一个 `harness.tblsPath` 设置指定 `tbls.exe` 的绝对路径，找不到时引导用户去设置——新用户门槛较高。本目录讨论改进方案。

## 关键结论速览

1. **不放在 VS Code 扩展包**。VS Code / Cursor 不允许扩展包内含可执行文件（[VS Code Marketplace 政策](https://code.visualstudio.com/api/working-with-extensions/publishing-extension#artifacts)），会审查失败；而且 `tbls.exe` 一份二进制 8–20 MB，三个平台加起来会让插件包臃肿。本目录讨论的"内置默认路径"实际是**随插件的辅助二进制**——技术上只能放进 `globalStorage`、或作为可选依赖、或者运行时下载。
2. **推荐方案是"默认路径指向 globalStorage + 找不到时一键下载"**：插件首次启动时把一个内置的 `tbls.exe`（随插件 ship，但放在用户写权限可及的位置）作为默认候选；如果默认位置没有 / 不可执行，引导用户去设置界面下载（GitHub Releases 选对应平台 / 架构的资产），下载后再走原来的流程。
3. **手动指定路径的能力保留并增强**。既有的 `harness.tblsPath` 设置保留（用户可能就是想用自己机器上的 tbls，比如 Homebrew 装的、系统级部署的），设置页面提供"测试一下"按钮，立刻验证当前配置能不能跑。
4. **不引入自动更新**。tbls 自己有版本策略，插件不替它做。手动"检查新版本"按钮足够。

详细论证见各文档。
