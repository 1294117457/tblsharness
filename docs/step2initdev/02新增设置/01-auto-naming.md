# 01 默认名称、内部 ID 和新的新建流程

## 一、原则

- **用户只和名称打交道。** 名称有默认值，可以随时修改，可以重复（但默认名称会自动编号，不会重复）。
- **ID 只给程序用。** 由插件生成，创建后不变，界面上不显示。只在鼠标悬停的提示里显示一行"ID：design3"，方便在存储目录里找到对应的文件夹。
- **点一下就创建。** 新建操作不弹输入框。需要用户做选择的只有数据库连接，它有专门的页面（见 02 文档）。

## 二、ID 的生成

### 2.1 格式

| 类型 | ID 格式 | 例子 | 对应位置 |
| :-- | :-- | :-- | :-- |
| 工作区 | `workspace<N>` | `workspace1` | `<根目录>/workspaces/workspace1/` |
| 设计模型 | `design<N>` | `design1` | `workspace1/design/design1/` |
| 数据库 | `db<N>` | `db1` | `workspace1/db/db1/` |
| 画布 | `canvas<N>` | `canvas1` | `workspace1/canvas/canvas1.canvas.json` |

- 这些 ID 都符合现有的 ID 规则（`validateId`），存储结构、画布引用、凭据键名都不用改。
- 工作区的序号在全局范围内递增；设计模型、数据库、画布的序号在所属工作区内各自递增。
- 已经用旧流程创建的 ID（比如 `order-system`）继续有效，不做改名。

### 2.2 为什么序号只增不减

如果删掉 `design2` 后，下一个新建的设计模型又叫 `design2`，会出现下面的问题：

- 别的画布的撤销记录里可能还引用着 `design2`。撤销"移除数据源"之后，画布会指向这个新的、完全不相关的设计模型，而且不会有任何报错。
- 如果某次删除没有清理干净（比如删除时插件崩溃），残留的凭据、对比记录会被新的数据源"继承"。

所以序号只增不减，被删除的 ID 永远不再使用。

### 2.3 序号保存在哪里

| 序号 | 保存位置 | 字段 |
| :-- | :-- | :-- |
| 工作区 | `<根目录>/harness.json`（新增，只存插件自己的元数据） | `{ "version": 1, "seq": { "workspace": 3 } }` |
| 设计模型、数据库、画布 | 工作区的 `workspace.yml` | `seq: { design: 2, db: 1, canvas: 4 }` |

- 文件不存在或字段缺失时，从现有目录名里找出最大的数字编号，加一作为起点。这样旧数据和手动拷进来的目录都能兼容。
- 新建时的顺序：读取序号 → 序号加一 → 用这个 ID **独占地**创建目录（目录已存在就失败）→ 写回序号 → 写入其他文件。
- **多个 Cursor 窗口同时新建**时（它们共用同一个存储目录），可能读到同一个序号。独占创建会让其中一个失败，失败的一方把序号再加一重试，最多重试 20 次。独占创建用 Node 的 `fs.promises.mkdir(path)`（不加 `recursive`，目录已存在时报 `EEXIST`）。画布文件用 `fs.promises.writeFile(path, text, { flag: 'wx' })`。`vscode.workspace.fs.createDirectory` 在目录已存在时不会报错，所以这里不能用它。

新增纯函数（放在 `src/shared/workspace.ts`，便于单元测试）：

```ts
/** 从已有 ID 和记录的序号中，算出下一个序号 */
function nextSeq(prefix: string, existingIds: string[], recorded?: number): number;

/** "工作区 1"、"工作区 2"……取已有同类默认名称中最大的编号加一 */
function nextDefaultName(base: string, existingNames: string[]): string;
```

### 2.4 默认名称

| 类型 | 默认名称 | 说明 |
| :-- | :-- | :-- |
| 工作区 | 工作区 1、工作区 2… | |
| 设计模型 | 设计模型 1… | 从数据库复制时用"<数据库名称> 的设计" |
| 数据库 | `<数据库类型> · <库名>`，例如"PostgreSQL · orders" | 在连接页面里可以修改。**不包含主机地址**，因为名称会写进 `source.yml`，而主机地址属于连接信息，只存在凭据里（见 02 文档第五节） |
| 画布 | 画布 1… | |

默认名称的编号和 ID 的序号是两回事：编号只看现有名称，取最大编号加一。比如现有"画布 1"、"画布 2"，删掉"画布 2"后，下一个默认名称又是"画布 2"，而 ID 是 `canvas3`。名称可以重复，不影响任何功能。

同一个工作区里连接了两个同名的库（比如测试环境和生产环境都叫 `orders`）时，第二个的默认名称是"PostgreSQL · orders (2)"，用户可以在连接页面里改成"orders 测试环境"之类的名称。

## 三、新建流程

### 3.1 新建工作区

入口：视图标题栏的 `+`、欢迎页的"新建工作区"按钮。

1. 分配 ID `workspace<N>`，名称"工作区 N"。
2. 创建 `workspace.yml`、`comparisons.json`、`design/`、`db/`、`canvas/`，以及一个空画布"画布 1"（`canvas1`）。
3. 在树中展开并选中新工作区。
4. 右下角显示一条不需要操作的提示："已创建工作区 1，按 F2 可以重命名"。

不再弹出"接下来要做什么"。三个空分组里的灰色提示行（"还没有设计模型，点击 + 新建"）已经起到引导作用。

### 3.2 新建设计模型

设计模型属于工作区：在哪个工作区里新建，就显示在哪个工作区的"设计"分组下，文件放在这个工作区的 `design/<ID>/` 目录里（`source.yml`、`schema.json`、`ext.json`）。**新建后不自动加入任何画布，也不打开画布。**

入口一：设计分组行尾的 `+`，**直接创建空白设计模型**：

1. 分配 ID `design<N>`，名称"设计模型 N"。
2. 目标数据库类型按下面的顺序决定，不询问用户：
   1. 工作区里有数据库数据源时，用最近一次同步的那个数据库的类型（快照里的 `driver.name`）；
   2. 否则用上一次新建设计模型时的类型（保存在 `context.globalState`）；
   3. 都没有就用 `postgres`。
3. 写入 `design/design<N>/` 下的三个文件。
4. 在树中展开这个工作区的"设计"分组，选中新节点。节点描述显示"PostgreSQL · 0 张表"。
5. 右下角显示一条不需要操作的提示："已创建设计模型 1（PostgreSQL）。按 F2 重命名，右键可以更改数据库类型或添加到画布"。

之后要在画布上编辑它，有两种方式：

- 画布左侧数据源面板的"+ 添加"，列表里会出现这个设计模型；
- 设计模型节点右键"添加到画布…"（已有命令 `harness.source.addToCanvas`）。

入口二：设计分组和工作区的右键菜单"新建设计模型"子菜单：

| 子菜单项 | 行为 |
| :-- | :-- |
| 空白 | 同入口一 |
| 从数据库复制… | 工作区里只有一个有快照的数据库时直接复制；有多个时弹出选择。名称默认"<数据库名称> 的设计"，目标数据库类型取自快照 |
| 从 tbls JSON 文件导入… | 选择文件，名称默认取 JSON 里的 `name`，没有就用"设计模型 N" |

三种方式创建完成后的行为相同：只在树中显示并选中，不加入画布。

VS Code 的树视图行尾按钮不支持下拉菜单，所以这些选项放在右键子菜单里（`contributes.submenus`）。

**修改目标数据库类型：** 设计模型右键新增"目标数据库类型…"（`harness.design.setDriver`），修改 `schema.json` 的 `driver.name`。已有字段的类型不会自动转换，提示里说明这一点。

### 3.3 新建画布

入口：画布分组行尾的 `+`、工作区右键。

1. 分配 ID `canvas<N>`，名称"画布 N"，内容为空。
2. 立即打开。画布的空状态已经提示"在左侧数据源面板添加设计模型或数据库"。

不再在新建时选择数据源、表的显示方式和对比，这些都在画布里操作。

### 3.4 添加数据库

入口：数据库分组行尾的 `+`、工作区右键。打开连接页面，先选择数据库类型，再填写连接参数，详见 [02-connection-page.md](./02-connection-page.md)。

连接成功后，数据库显示在这个工作区的"数据库"分组下并选中，**不自动加入画布**。

### 3.5 画布数据源面板里的"新建"

画布左侧"+ 添加"菜单中的"新建设计模型…"和"添加数据库…"，行为和树视图里完全一样：新建的数据源只出现在工作区里，**不自动加入当前画布**。创建完成后，"+ 添加"菜单的列表会刷新，用户在列表里点一下就能加入当前画布。

这样所有入口的规则一致："新建"只负责创建数据源，"添加"才负责放进画布。

## 四、重命名

树视图不支持直接在节点上编辑文字，所以提供这几种方式：

| 方式 | 说明 |
| :-- | :-- |
| 右键"重命名" | 保持现有行为：弹出一个输入框，默认值是当前名称 |
| F2 | 在 Harness 树视图里选中节点后按 F2，等同于右键"重命名"。新增一个快捷键绑定：`"when": "focusedView == harness.workspaces"`，命令 `harness.rename` 根据节点类型转给对应的重命名命令 |
| 画布工具栏 | 点击画布名称直接编辑，回车确认。这是一次画布修改（新增画布操作 `meta.set`），可以撤销，保存画布时写入 |
| 画布数据源面板 | 双击数据源名称直接编辑，改的是数据源的 `source.yml`，立即生效 |

画布名称改了但还没保存时，树视图显示的仍然是文件里的旧名称。为了避免这种不一致，树视图的画布节点优先使用已打开的画布文档里的名称（`CanvasEditorProvider` 提供一个查询方法）。

## 五、要删掉的东西

- `promptId`，以及所有调用它的地方。
- `harness.workspace.create`、`harness.design.create`、`harness.canvas.create` 里的 `promptName`、`showQuickPick` 步骤。
- `harness.db.create` 里的输入框流程，改为打开连接页面。
- `harness.db.setConnection` 的输入框，改为用连接页面编辑（见 02 文档第七节）。
- 新建画布时"选择数据源、全部还是挑选、是否对比"三步。
- 新建设计模型后的"在新画布中打开 / 添加到已有画布"询问。
- 新建数据库后的"现在同步结构吗？"询问（连接页面在连接时已经读取了结构）。
