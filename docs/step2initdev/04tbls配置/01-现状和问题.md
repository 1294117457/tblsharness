# 01 现状和问题

## 一、当前实现

### 1.1 设置项

`package.json#contributes.configuration.properties`：

```json
"harness.tblsPath": {
  "type": "string",
  "default": "tbls",
  "description": "tbls 可执行文件路径。tbls 在 PATH 里时保持默认值即可。"
}
```

调用方统一从配置里取：

- `src/commands/db.ts:36` — `tbls sync` 命令
- `src/connection/connectionPanel.ts:224` — 连接页面的测试 / 连接
- `src/canvas/canvasEditor.ts` 中通过 `harness.db.sync` 间接调用

```ts
const config = vscode.workspace.getConfiguration('harness');
const tblsPath = config.get<string>('tblsPath', 'tbls') || 'tbls';
```

`runner.ts` 用 `execFile(file, args, ...)` 启动（不走 shell），找不到时返回 `ENOENT`，转成：

```ts
new TblsError(`找不到 tbls 可执行文件：${file}。请在设置 harness.tblsPath 中配置 tbls 的完整路径。`, 'notFound')
```

错误最终在 `connection/errors.ts` 里被识别为 `action: 'setTblsPath'`，调用方弹出 `["设置 tbls 路径"]` 按钮跳到 `workbench.action.openSettings` + `harness.tblsPath`。

### 1.2 当前用法的隐含假设

- 用户机器上**已经装好 tbls**（`brew install tbls`、`scoop install tbls`、Go 工具链 `go install` 等等）。
- 用户知道 `tbls` 在哪里：要么在 `PATH`（设置保持默认 `tbls`），要么有可写的绝对路径填进设置。

## 二、新用户的实际路径

| 路径 | 是否顺畅 |
| :-- | :-- |
| macOS 用户装过 Homebrew，跑过 `brew install tbls` | 顺畅 |
| Linux 用户 `apt install tbls` 或 Go 工具链安装 | 顺畅 |
| Windows 用户在 PowerShell 里跑 `scoop install tbls` | 顺畅 |
| **Windows 用户没用过包管理器** | ❌ 不知道 tbls 是什么 → 不会主动装 |
| **企业内网用户**，不能随便装第三方二进制 | ❌ 让用户去找 IT 装软件 |
| **macOS 用户没装 Homebrew**（如公司发的机器禁用了） | ❌ 需要先去装 Homebrew |

新插件首次启动后，用户**第一步**通常是点"添加数据库"，**第一个**弹窗就是"找不到 tbls"。这不是合理的入门体验。

## 三、tbls 自身的发布形态

[k1LoW/tbls releases](https://github.com/k1LoW/tbls/releases) 提供了：

- Linux：`tbls_VERSION_linux_amd64.tar.gz`、`tbls_VERSION_linux_arm64.tar.gz`
- macOS：`tbls_VERSION_darwin_amd64.tar.gz`、`tbls_VERSION_darwin_arm64.tar.gz`（Apple Silicon）
- Windows：`tbls_VERSION_windows_amd64.zip`（i386 也提供但 amd64 是主流）
- Go 安装：`go install github.com/k1LoW/tbls/cmd/tbls@latest`
- Homebrew：`brew install tbls`
- Scoop：`scoop install tbls`
- 各 Linux 发行版的包：Debian / Ubuntu / Fedora / Arch（取决于上游仓库，可有可无）

**特点**：

1. 跨平台、纯 Go 写出来的单个二进制，**没有运行时依赖**。下载下来改个名加执行权限就能用。
2. 体积：解包后二进制约 15–20 MB，压缩包 5–8 MB。
3. 发布节奏稳定，最近一个版本 1.96.0。
4. **没有官方升级通知机制**（不内置 `--check-update`），版本升级靠包管理器或用户主动下载。

## 四、VS Code 扩展对二进制分发的限制

- **VS Code Marketplace 政策**禁止把"unsafe 的可执行文件"打进 `.vsix`（参考 [Publishing Extensions / Artifacts](https://code.visualstudio.com/api/working-with-extensions/publishing-extension#artifacts)）。`tbls.exe` 不在白名单里。把 `tbls.exe` 直接塞进扩展的 `media/` 或 `bin/` 目录会导致：
  1. 扩展审核被拒（如果是 Marketplace 发布）。
  2. 一些企业环境会扫描扩展包，发现非常规可执行文件会直接屏蔽。
- Cursor / VS Code 走的是**扩展的全局存储目录**（`context.globalStorageUri`），那里**对扩展是可写的**；扩展可以把二进制放进去。
- 三个平台每个一份 20 MB，加起来 60 MB，会让首次安装变慢——所以"内置默认路径"必须做"按平台只下载/放置当前需要的"。

## 五、现有命令的报错提示

`runner.ts` 的报错路径覆盖了：

- `ENOENT`（找不到）→ 提示设 `harness.tblsPath`（OK，但只跳设置，不带"下载"）
- 超时（`killed && timeoutMs`）→ 提示调 `harness.tblsTimeoutSeconds`（OK）
- 用户取消 → 不报错（OK）
- 其他错误 → 原始错误 + 掩码后的密码

**缺**的是：在"找不到"时给一个更进一步的引导（下载、官方安装命令、说明文档链接）。当前只是跳设置页让用户去查文档。
